# Vocab Zombie: IELTS Survival — การปรับเปลี่ยนครั้งใหญ่
## อาวุธ · เสียง · ซอมบี้ · เมนูหลัก · HUD · คำอธิบายคำตอบ

### บทบาท
คุณคือ Senior FPS Game Developer, Technical Artist (Three.js/WebGL), 3D Animation Designer, Sound Designer (Web Audio API), UI/UX Designer และ Gameplay Systems Engineer ที่เชี่ยวชาญเกมแนว Zombie Survival FPS และ Survival Horror

งานนี้คือการอัปเกรดเกมที่มีอยู่แล้ว ไม่ใช่สร้างใหม่ ทุกระบบต้องเชื่อมกันผ่าน event กลาง ห้ามทำแอนิเมชัน เสียง หรือเอฟเฟกต์ที่แยกขาดจากกัน ให้เน้นความสมจริงทางภาพ ความลื่นไหลของแอนิเมชัน การซิงก์เสียงกับภาพ ความชัดเจนของ UI และประสิทธิภาพ

### ขอบเขตงาน
- **A. ระบบอาวุธ**: viewmodel animation, Weapon State Machine, recoil, reload แบบแบ่งช่วง, รูปลักษณ์ปืน, muzzle flash / smoke / impact
- **B. ระบบเสียงทั้งเกม**: mixer, เสียงปืนหลายชั้น, เสียงรีโหลด, ฝีเท้าตามพื้น, reverb ตามโซน, spatial audio, occlusion
- **C. ซอมบี้ใหม่ทั้งหมด 10 แบบ**: รูปร่าง ใบหน้า เสื้อผ้า texture แอนิเมชัน เสียง
- **D. หน้าเมนูหลักใหม่** แทนหน้า Tap To Lobby และย้ายเมนูจากลอบบี้มาไว้ที่นี่
- **E. HUD ใหม่** กลางล่างแบบ Minecraft และย้าย Wave / จำนวนซอมบี้ไปไว้ที่กล่องคำถามด้านบน
- **F. ทุกคำถาม**: ตอบผิดต้องอธิบายว่าทำไมผิดพร้อมสาเหตุ ตอบถูกก็อธิบายสั้น ๆ ด้วย

2. **หากมีระบบเดิมอยู่แล้ว ให้ตรวจสอบระบบเดิมก่อนสร้างใหม่ และหลีกเลี่ยงการเขียนทับโค้ดหรือไฟล์ที่ไม่เกี่ยวข้อง**
3. **ห้ามแต่ง API**: ใช้เฉพาะ API ที่มีจริงใน Three.js เวอร์ชันที่โปรเจกต์ใช้ และ Web Audio API มาตรฐาน อย่าเขียนโค้ดที่อ้างว่าใช้งานได้ทันทีโดยไม่ได้ทดสอบ ถ้าข้อมูลไม่พอ ให้ระบุสมมติฐานในสรุปแล้วเลือกทางที่ย้อนกลับง่าย ถามผู้ใช้ก่อนเฉพาะเรื่องที่ย้อนกลับยาก
4. **ห้ามลบหรือทำฟีเจอร์เดิมพัง** เช่น perk, บอส 10 ตัว (ชื่อ/พลัง/cutscene), ability แบบรวงผึ้ง, SRS/Daily Review, ระบบ 4 ภาษา, ปุ่ม touch ที่ปรับขนาด/ย้ายได้, การปรับขนาด HUD, quality tiers, FPS cap, checkpoint เวฟ 10, mystery box, ปืนติดผนัง, story notes, ประตูเลื่อน, update flow ถ้าจำเป็นต้องเปลี่ยนพฤติกรรม ให้แจ้งในสรุป
5. **ข้อความทุกตัวผ่านไฟล์ strings (i18n)** ห้าม hardcode และข้อความใหม่ต้องมีครบ 4 ภาษา (ไทย อังกฤษ จีน ฝรั่งเศส) **ค่าที่ปรับจูนได้ทั้งหมดอยู่ใน config** (weapon / audio / zombie / hud / menu หรือรวมกับ config เดิมตามโครงสร้างที่มี) ตัวเลขใน prompt นี้เป็น "ค่าเริ่มต้นแนะนำ" ปรับได้
6. **Popup/หน้าต่างทุกอันใช้ openModal/closeModal กลาง** (cursor, pointer lock, pause, ปิด hotkey ที่ชนกัน)
7. **Gameplay คือแหล่งความจริง (source of truth)**: กระสุน HP stamina เงิน และสถานะรีโหลด มาจาก Game State เท่านั้น แอนิเมชัน เสียง VFX และ UI เป็นผู้แสดงผลจาก event ห้ามให้แอนิเมชันเป็นตัวกำหนดค่าจริง
8. **เวลา**: ใช้ delta-time และ "game time" ที่หยุดเมื่อ pause หรือเปิด modal แอนิเมชัน เสียงที่ผูกกับจังหวะ และ timer ต้องหยุดและเล่นต่อพร้อมกัน
9. **ประสิทธิภาพ**: object pooling, ไม่สร้าง object/closure ใหม่ทุกเฟรมใน hot path, dispose เมื่อเลิกใช้, ไม่ spawn เอฟเฟกต์ที่อยู่นอกจอหรือไกลเกินมองเห็น, ทุกฟีเจอร์มีระดับตาม quality tier (ตารางในรอบ 8) เป้าหมาย: desktop High ≥ 60 FPS และ iPad Medium ≥ 30 FPS ในฉากที่มีซอมบี้เต็มเวฟ
10. **ความสบายตาและหู**: เคารพค่าตั้ง Accessibility ทุกตัว ห้ามแสงวาบหรือกะพริบเต็มจอหรือพื้นที่ใหญ่เกิน 3 ครั้งต่อวินาที ห้ามเสียงดังตกใจซ้ำ ๆ
11. **ไฟล์ใน `public/` ต้องเล็กกว่า 25 MiB ต่อไฟล์** (ข้อจำกัด Cloudflare) ฟอนต์และไฟล์ใหม่ต้องถูก cache โดย service worker
12. **ทดสอบผ่าน local server** (เช่น `npx wrangler dev`) ไม่ใช่เปิดไฟล์แบบ `file://` และใช้ Playwright/headless Chromium จับภาพหน้าจอตรวจ layout หลายอัตราส่วนเมื่อทำได้
13. **หน้า Lab และ debug** (`?debug=1`, `?lab=weapons`, `?lab=sound`, `?lab=zombies`) ต้องโหลดแยก (lazy) ไม่เพิ่มขนาดตอนเล่นปกติ
14. **ทำทีละรอบตามลำดับ**: จบแต่ละรอบ → ตรวจบั๊กเอง → เจอแล้วแก้ทันที → อัปเดต `docs/overhaul/progress.md` (ทำแล้ว / เหลือ / ปัญหา) → commit ด้วยข้อความชัดเจน → เขียนสรุปผลรอบนั้น → ไปรอบถัดไปได้เลย ยกเว้นเจอเรื่องที่ต้องให้ผู้ใช้ตัดสินใจ หรือพบในรอบ 0 ว่าสเปกขัดกับระบบเดิมอย่างมีนัยสำคัญ (ให้หยุดถามก่อน)
15. ถ้าไฟล์ prompt นี้ยังไม่อยู่ใน repo ให้บันทึกไว้ที่ `docs/overhaul/PROMPT.md` เพื่อให้ session ใหม่อ่านต่อได้ ถ้า context ใกล้เต็ม ให้จบงานย่อยปัจจุบันให้เรียบร้อยและอัปเดต `progress.md` ก่อน

## รอบ 1 — Weapon State Machine + แอนิเมชันมุมมองบุคคลที่หนึ่ง

### 1.1 โครงสร้าง
- **WeaponStateMachine กลางหนึ่งตัว** เป็นเจ้าของการเปลี่ยนสถานะทั้งหมด Gameplay และ Input ส่งเป็น "คำขอ" (`requestFire`, `requestReload`, `requestAim`, `requestSwitch(slot)` ฯลฯ) state machine ตรวจกติกาแล้วจึงเปลี่ยนสถานะและส่ง event ออกไป Animation, Audio, VFX และ UI Controller **ฟังอย่างเดียว ห้ามเปลี่ยนสถานะเอง** เพื่อป้องกันการเปลี่ยนสถานะขัดกัน
- แอนิเมชันแบบชั้น: Base locomotion (idle/walk/sprint blend ตามความเร็ว) → Action layer (fire / reload / switch / inspect / melee) → Additive layer (recoil, การหายใจ, ลงพื้น, โดนตี) → Aim weight 0..1
- ข้อมูลแอนิเมชันแบบ data-driven ต่อ **ตระกูลอาวุธ** (pistol, revolver, SMG, rifle, shotgun pump, shotgun semi, sniper bolt-action, LMG, special, knife) + ค่า override ต่อกระบอก ไม่ต้องทำมือทีละกระบอกทั้ง 60 กว่ากระบอก
- ใช้ keyframe + curve (หรือ AnimationMixer ถ้าโปรเจกต์ใช้อยู่) สำหรับท่ารีโหลด สลับปืน และ inspect ส่วน recoil, sway และ bob ใช้ spring/damper แบบ procedural

### 1.2 สถานะ
Idle, Walking, Sprinting, Aiming, Firing, Recovering, Reloading, Inspecting, Lowered, Switching, Disabled และ **Melee** (มีด)

ทุกสถานะต้องเขียนในตาราง: เงื่อนไขเข้า/ออก, สถานะที่ไปต่อได้, แอนิเมชันที่ใช้, เสียงและ VFX ที่อนุญาต, การตอบสนองของ UI, guard กันการเข้าซ้ำ, วิธีจัดการเมื่อ animation event มาช้าหรือไม่มา และ watchdog (ถ้าค้างเกินเวลาสูงสุด → กลับสู่สถานะที่ถูกต้อง + log เตือนใน dev mode)

กติกาเริ่มต้น (ปรับใน config):
- **Firing**: เข้าได้จาก Idle / Walking / Aiming / Recovering เมื่อ fire cooldown พร้อมและมีกระสุน จาก Sprinting ต้องผ่าน sprint-out delay ก่อน ถ้าอยู่ใน Inspecting ให้ยกเลิกทันทีแล้วยิง ถ้าอยู่ใน Lowered ต้องยกปืนขึ้นก่อน (สั้น ๆ) กระสุนหมด → เสียง dry-fire ครั้งเดียว แล้วรีโหลดอัตโนมัติถ้าเปิด Auto Reload ไว้
- **Aiming**: ห้ามระหว่าง Sprinting / Switching / Reloading ถ้ากดเล็งค้างระหว่างรีโหลด ให้เข้า Aiming ทันทีที่รีโหลดเสร็จ
- **Lowered**: ตอนกด E โต้ตอบ, อ่าน note, เปิด modal, ช่วงพักระหว่างเวฟ
- **Disabled**: ตาย, cutscene บอส, เปลี่ยนด่าน, loading
- **Switching**: ลดปืนเก่า → ยกปืนใหม่ เวลาขึ้นกับน้ำหนักปืน (ระบบน้ำหนักเดิม) กดสลับรัว ๆ ให้จำเฉพาะช่องสุดท้ายที่ขอ และยกเลิกรีโหลดหรือ inspect ที่ค้างอยู่
- **Melee (มีด)**: ใช้ hit-frame event ตัดสินการโดน ถ้าเกมมี quick-melee อยู่แล้วให้ใช้ระบบเดิม

### 1.3 รีโหลดแบบแบ่งช่วง (แยกภาพออกจากข้อมูลกระสุน)
- **Start**: เปลี่ยนเข้าท่ารีโหลด ลดปืนลงอย่างนุ่มนวล มือเคลื่อนให้เห็นชัด เสียงเริ่มตาม animation event ไม่กระตุก
- **Motion**: ชิ้นส่วนขยับจริง (แม็กออก/เข้า, สไลด์/โบลต์, ใส่ลูกทีละนัด) มือกับ weapon rig สอดคล้องกัน มือไม่ทะลุปืน แบ่งช่วงให้เข้าใจง่าย ไม่ต้องจำลองกลไกจริงละเอียด เน้นความชัดของภาพ ความตรงของเสียง และความลื่นของเกมเพลย์
- **Completion**: กลับสู่ท่าพร้อมยิง UI อัปเดตเมื่อ gameplay ยืนยันเท่านั้น เสียงยืนยันสั้นกระชับ แล้วคืนการควบคุม
- มี 2 แบบ: **tactical** (ยังมีกระสุนในแม็ก — สั้นกว่า) และ **empty** (แม็กหมด — มีจังหวะปล่อยสไลด์/โบลต์)
- ปืนบรรจุทีละนัด (ลูกซอง ฯลฯ) ใช้ reload แบบ loop ทีละนัด กดยิงเพื่อหยุดหลังนัดปัจจุบันได้
- **Commit point**: gameplay เปลี่ยนจำนวนกระสุน "ครั้งเดียว" ที่จุด commit (ค่าเริ่มต้นประมาณ 70% ของเวลารีโหลด หรือ event `magIn`) ใช้ `reloadId` กันอัปเดตซ้ำ ถ้า event ไม่มาภายในเวลาที่กำหนด + 150 ms ให้ gameplay commit เองตาม timer โดยเสียงต้องไม่เล่นซ้ำ

ตารางยกเลิกรีโหลด (ค่าเริ่มต้น):

| เหตุการณ์ระหว่างรีโหลด | ผล | กระสุน |
|---|---|---|
| สลับอาวุธ | ยกเลิก | ก่อน commit = ไม่เปลี่ยน / หลัง commit = เติมแล้ว |
| ใช้มีดหรือ quick melee | ยกเลิก | เหมือนบรรทัดบน |
| กดยิง (ยังมีกระสุนในแม็กและยังไม่ถึง commit) | ยกเลิกแล้วยิง (`fireCancelsReload`) | ไม่เปลี่ยน |
| วิ่ง (Sprint) | ไม่ยกเลิก รีโหลดต่อโดยผสมท่าวิ่ง (`sprintCancelsReload: false`) | ตามปกติ |
| โดนตี | ไม่ยกเลิก เล่น flinch แบบ additive | ตามปกติ |
| เปิด modal / pause | หยุดชั่วคราว แล้วเล่นต่อจากจุดเดิม | ตามปกติ |
| ตาย / Game Over / เปลี่ยนด่าน | reset ทั้งหมด → Disabled | reset ตามกติกาเดิม |

เสียงและ VFX ที่ผูกกับแอนิเมชันที่ถูกยกเลิก ต้องหยุดหรือ fade ทันที (ติดตามด้วย animation instanceId) และต้องไม่มีสถานะค้างหรือข้อมูลไม่ตรงกัน

### 1.4 ท่าทางแต่ละสถานะ
- **Idle**: ขยับเบา ๆ ตามจังหวะหายใจ (sine ผสม noise ความถี่ต่ำ ไม่ใช่การสั่นสุ่มที่ผิดธรรมชาติ) แขนและมือขยับเล็กน้อย และหายใจแรงขึ้นเมื่อ stamina ต่ำ
- **Walk**: bob ขึ้นลงนุ่ม ๆ จังหวะเดียวกับเสียงฝีเท้าและ camera bob เดิม การแกว่งของมือสัมพันธ์กับจังหวะเดิน แรงตามความเร็ว มี motion smoothing
- **Sprint**: ท่าถือปืนต่างจากปกติ (เอียงหรือลดต่ำ) จังหวะตามการวิ่ง ปิดการเล็ง ออกจากวิ่งมี sprint-out delay ตามน้ำหนักปืน (เบา 0.10 / กลาง 0.18 / หนัก 0.25 วินาที) กลับสู่ท่าปกตินุ่มนวล กล้องห้ามเหวี่ยงแรงจนเวียนหัว
- **Aim**: ใช้ระบบเล็ง/ซูมคลิกซ้ายและ reticle เดิม เพิ่มการเปลี่ยนท่าแบบ ease-in/out ตามน้ำหนัก (0.15 / 0.22 / 0.30 วินาที) ลด sway และ bob ตอนเล็ง ตำแหน่งปืนตรงกับกล้อง ไม่เปลี่ยนตำแหน่งฉับพลัน
- **Inspect**: ใช้ปุ่มว่างที่กำหนดใน key remap (controller และ touch ตามความเหมาะสม) โชว์ปืนอย่างสวยงาม ไม่รบกวนการควบคุมตัวละคร ยกเลิกได้ทันทีด้วยทุก action
- **Lowered**: ลดปืนลงนุ่ม ๆ ยกกลับได้เร็ว
- **Firing (multi-stage)**: event ยิงจาก gameplay → muzzle flash → weapon kick (translation ถอยหลัง + rotation เงยขึ้น) → camera recoil (แยกจาก weapon recoil และปรับ/ปิดได้ใน Accessibility) → มือ/แขน follow-through → recovery ตาม curve ปืนอัตโนมัติ recoil สะสมแต่มีเพดาน และกลับนุ่ม ๆ เมื่อปล่อยไก หนึ่ง event ยิง = เอฟเฟกต์หนึ่งชุด (กันเล่นซ้ำด้วย eventId)
- **Recovery**: กลับตำแหน่งตาม curve ไม่กระตุกเมื่อยิงต่อเนื่อง ผสมกับ idle / walk / aim / sprint ได้ โดย state machine เป็นผู้ตัดสินว่าท่าไหนเริ่มได้
- **โดนตี**: flinch เล็ก ๆ แบบ additive ตามค่า Camera Shake

### 1.5 Viewmodel
- ใช้ viewmodel render pass แยกที่มีอยู่ (ซึ่งแก้ปัญหาเส้นบาง/z-fighting ไปแล้ว — ห้ามทำให้กลับมา)
- ตำแหน่งและมุมปืนปรับตามอัตราส่วนจอและ FOV: ปืนอยู่ช่วงล่างของจอ ไม่บังเป้ากลางจอ ทดสอบที่ 16:9, 4:3 (iPad), 19.5:9 (มือถือแนวนอน), 21:9
- มือและแขนสอดคล้องกับตัวละครผู้เล่นทรงบล็อกเดิม สัดส่วนปืน มือ แขนเข้ากัน ตรวจทุกตระกูลอาวุธที่ท่าสำคัญว่ามือไม่ทะลุปืนและโมเดลไม่หลุดตำแหน่งจากกล้อง
- **Viewmodel Visibility Control**: ซ่อน viewmodel ตอน cutscene, ตาย, เปลี่ยนด่าน และแสดงกลับพร้อมสถานะที่ถูกต้อง

### 1.6 Animation Events + ระบบตรวจสอบ
- ทุกแอนิเมชันมี marker (เช่น reload: `start`, `magOut`, `magIn`, `boltRelease`, `end` / fire: `shot` / melee: `hit`) ส่งพร้อม instanceId และแต่ละ marker ส่งได้ครั้งเดียวต่อ instance ใช้ซิงก์เสียง, VFX, camera feedback, UI update และ state transition
- Dev validator ตรวจ: event ที่ไม่ถูกเรียก (ส่ง fallback ครั้งเดียว + warn), event ซ้ำ (ignore + warn), แอนิเมชันถูกยกเลิกกลางทาง (cleanup), สลับปืนระหว่างแอนิเมชัน (cleanup เสียงและ VFX ของปืนเก่า), กลับเข้าเกมหลัง pause, UI ไม่ตรงกับ gameplay (เช็กทุกเฟรมใน dev) ถ้าระบบแอนิเมชันล้มเหลวหรือถูกขัด ต้องคืนระบบไปยังสถานะที่ถูกต้องได้เสมอ
- **Debug overlay** (`?debug=1`): สถานะปืน, event 10 ตัวล่าสุด, แอนิเมชันที่เล่นอยู่ (ใช้ต่อในรอบอื่นเพื่อแสดงจำนวนเสียง, particle, draw calls, frame time)
- **Weapon Lab** (`?lab=weapons`): เลือกปืนทุกกระบอก กดดูยิง / รีโหลด (ทั้งสองแบบ) / สลับ / inspect ได้ มีปุ่ม slow-motion ให้ผู้ใช้ตรวจเอง

### เกณฑ์ผ่านรอบ 1
- unit test ของ state machine ที่รันใน Node ได้: ทุก transition ในตาราง + **fuzz test** สุ่มกดปุ่ม 10,000 ครั้งแล้วยืนยัน invariant (ไม่มีสถานะค้าง, กระสุนไม่ติดลบและไม่เกินแม็ก, ไม่ commit ซ้ำ)
- เปลี่ยนสถานะไม่กระตุก และ pause / resume กลางรีโหลดได้ถูกต้อง

## รอบ 2 — รูปลักษณ์อาวุธ + Muzzle Flash / Smoke / Impact

### 2.1 รูปลักษณ์ปืน (อัปเกรดทุกกระบอก ตามลำดับ โรงเรียน → โรงพยาบาล → บังเกอร์)
- Silhouette และสัดส่วนจำได้ทันทีในแต่ละตระกูล แยกชิ้นส่วน (body, slide/bolt, แม็ก, ไก, ศูนย์เล็ง, พานท้าย) เป็น group แยกเพื่อใช้ในแอนิเมชัน
- วัสดุแบบ voxel: **Dark Matte Metal, Worn Metal, Polymer, Rubber Grip, รอยขีดข่วน, ฝุ่นและคราบ, ขอบสึก (edge wear), specular ที่ควบคุมได้** ทำด้วย pixel texture ขนาดเล็ก (16–32 px, NearestFilter) + vertex color รายละเอียดพอเมื่อมองใกล้ แต่ไม่เกิด noise หรือระยิบในระยะเล่นจริง และไม่ให้ทุกวัสดุเงาเท่ากัน
- **คงสีเอกลักษณ์ของแต่ละกระบอกไว้** (ผู้ใช้เคยขอให้ปืนมีสีสัน ไม่ใช่ขาวดำ): ส่วนโลหะเป็นโทนเข้มหรือสึก แต่ส่วน polymer สีพ่น แถบ accent และสีตามความหายาก (rarity) ยังเด่น
- รายงานรายชื่อปืนที่อัปเกรดแล้วในสรุป

### 2.2 แสงบน viewmodel
- แสงของ viewmodel scene ต้องอิงสภาพแวดล้อม (ambient/hemisphere ของโซนปัจจุบัน + ทิศแสงจันทร์) ปืนต้องไม่สว่างจ้าในทางเดินมืด
- เงาระหว่างมือกับปืนแบบ fake (vertex AO) เพราะ viewmodel pass ไม่มีเงาจริง
- รับแสงวาบชั่วขณะจาก muzzle flash และระเบิดได้ ความแรงของการสะท้อน (env map intensity) ต่างกันตามวัสดุ

### 2.3 Muzzle Flash
- สั้น 40–60 ms รูปทรงตามตระกูล (pistol เล็ก, rifle ยาว, shotgun กว้าง) sprite 3–4 แบบสุ่มหมุน ขนาดเหมาะกับ art direction ไม่สว่างจนบังภาพ
- แสงสะท้อนบนพื้นผิวใกล้ ๆ ใช้ light จาก light pool คงที่ (ห้ามเพิ่ม/ลบ light ระหว่างเล่นเพื่อกัน shader recompile — ถ้ายังไม่มี pool ให้สร้าง PointLight สำรองไว้ตั้งแต่โหลดด่านแล้วเปิด/ปิดด้วย intensity)
- ปืนยิงเร็ว (มากกว่า 600 RPM) ลดความเข้มแสงวาบ และไม่ให้ทั้งฉากสว่างกะพริบตามทุกนัด
- ตั้งค่า **Muzzle Flash Intensity 0–100%** (0 = ไม่มีแสงวาบ เหลือ sprite จาง ๆ)

### 2.4 ควันและเอฟเฟกต์รอง
- particle จาก pool จางหายอย่างเป็นธรรมชาติ จำนวนจำกัดตาม tier ไม่บังศัตรู ป้ายคำ หรือ UI (ลด alpha ใกล้กลางจอ) และปิดบน Very Low

### 2.5 Impact ตามชนิดพื้นผิว
- สร้าง **surfaceType กลางชุดเดียว** ใช้ร่วมกันทั้ง impact, เสียงกระทบ และเสียงฝีเท้า: concrete, tile, wood, metal, glass, grass, dirt/mud, water, flesh (ซอมบี้)
- ติด tag ให้ทุกพื้นและผนังในแมพเดิม (ห้องเรียน, ห้องสมุดพื้นไม้, ทางเดิน, สนามฟุตบอล, สวนดอกไม้, หญ้ารก, หน้าต่างกระจก, โรงพยาบาล, บังเกอร์)
- เอฟเฟกต์: ฝุ่น + เศษปูน, เสี้ยนไม้, ประกายไฟ, เศษกระจก, ดินกระเด็น, น้ำกระเซ็น, โดนซอมบี้ (เลือดตามค่า Blood & Gore)
- รอยกระสุน (decal) จาก pool มีจำนวนสูงสุดตาม tier แล้วจางหาย
- ตำแหน่งกระทบอ่านง่าย particle เล็กและน้อย ไม่บังศัตรู
- hit marker เล็ก ๆ ที่ crosshair (และแบบ headshot) ถ้ายังไม่มี

### เกณฑ์ผ่านรอบ 2
จำนวน particle และ decal ไม่เกินงบตาม tier (ดูใน debug overlay) + ภาพหน้าจอปืนทุกตระกูลจาก Weapon Lab

## รอบ 3 — ระบบเสียงทั้งเกม

### 3.1 Audio Mixer กลาง
- Bus: **Master → Music, Weapons, SFX (ซอมบี้ / กระทบ / ฝีเท้า / อื่น ๆ), Ambient (สิ่งแวดล้อม), UI**
- Master มี compressor + limiter: ห้าม clipping peak ไม่เกินประมาณ −1 dBFS
- Ducking: ตอนบอสส่งสัญญาณโจมตี, cutscene, popup คำถาม → ลด Music ประมาณ 6 dB และ Ambient ประมาณ 4 dB (attack 0.1 วินาที, release 0.8 วินาที)
- Pause: เสียง gameplay หยุด แต่ UI bus ยังทำงาน (เสียงเมนู pause)
- ใช้ระบบปลดล็อกเสียงบน iOS เดิม (resume AudioContext ใน user gesture แรก)

### 3.2 Audio Event System
- ประเภท event: `WeaponEvent`, `MechanicalEvent`, `CharacterMovementEvent`, `EnvironmentReflectionEvent`, `UIEvent`, `ZombieEvent`, `AmbientEvent`
- แต่ละ event มี id/instanceId, ต้นทาง, ตำแหน่ง (ถ้ามี), priority และ cooldownKey และต้องเรียกเสียงที่ถูกต้องตามสถานะเกมและแอนิเมชัน
- **Voice pool** + จำกัดจำนวนเสียงพร้อมกันต่อหมวด (ค่าเริ่มต้น: ปืนผู้เล่น 6, กระทบ 8, เสียงซอมบี้ 6 + horde bed, ฝีเท้า 6, UI 4, ambient 4 และเพดานรวมตาม tier) เกินแล้ว steal ตัวที่ priority ต่ำหรือไกลที่สุด
- กันเล่นซ้ำจาก event เดียวกัน, cooldown สำหรับเสียงที่เกิดถี่, หยุดเสียงเมื่อวัตถุถูกทำลายหรือออกจากฉาก, ไม่สร้าง/ทำลาย audio node จำนวนมากโดยไม่จำเป็น, โหลดไฟล์เสียงอย่างมีประสิทธิภาพ

### 3.3 เสียงปืน
- คาแรกเตอร์: **Sharp, Punchy, Heavy, Cinematic** หัวเสียงฉับไวและคม เนื้อทุ้มหนักแน่น รายละเอียดย่านกลาง–สูงชัด หางลดลงเป็นธรรมชาติ ไม่แบน ไม่แห้ง ไม่เหมือนเสียงสังเคราะห์ราคาถูก คุมเสียงแหลมไม่ให้บาดหู (shelf/lowpass) และคุมทุ้มไม่ให้ขุ่นหรือกลบเสียงอื่น (highpass ประมาณ 40–60 Hz และลดย่านประมาณ 250 Hz เล็กน้อยถ้าขุ่น)
- ชั้นเสียง (แต่ละชั้นมีหน้าที่ชัด ไม่ซ้อนจนขุ่นหรือดังเกินจริง):
  1. **Main transient** — ความคมในจังหวะแรก
  2. **Body** — น้ำหนักและความรู้สึกของแรงปะทะ
  3. **Mechanical texture** — กลไกสั้น ๆ ซิงก์กับสไลด์/โบลต์ในแอนิเมชัน
  4. **Environmental tail** — ส่งเข้า reverb ของโซน
  5. **Distant reflection** (optional) — เสียงสะท้อนไกลเมื่ออยู่ในพื้นที่กว้างหรือกลางแจ้ง
- ต่อยอดระบบ "เสียงไม่ซ้ำกันทุกกระบอก" เดิม: ทำ **recipe ต่อตระกูล + พารามิเตอร์ต่อกระบอก** ใน config
- **Pre-render**: สร้างเสียงแต่ละชั้นด้วย OfflineAudioContext ตอนโหลด (ปืนในช่อง + ปืนที่อาจได้ในด่านนั้น ทยอย render เบื้องหลัง) แบบละ 4–6 variants แล้ว cache เป็น AudioBuffer ตอนยิงแค่เลือก buffer เพื่อประหยัด CPU สำหรับปืนอัตโนมัติและ iPad
- **Shot variation**: สุ่มแบบควบคุม (ห้ามซ้ำ variant ติดกัน, pitch ±2–4%, gain ±1 dB) ฟังแล้วยังเป็นปืนกระบอกเดิม ไม่เปลี่ยนโทนรุนแรง ไม่ได้ยินว่าเป็นไฟล์เดียวซ้ำ ระดับความดังสม่ำเสมอระหว่าง variant
- เขียนสคริปต์วัด peak / RMS ของทุกกระบอก (render แบบ offline) ให้ความดังใกล้กันในตระกูลเดียว และรายงานในสรุป — **ห้ามใช้ความดังสูงสุดเป็นวิธีเดียวสร้างความหนักแน่น** ให้ใช้ความคม เนื้อเสียง และไดนามิกแทน
- เสียง UI ของอาวุธ: dry-fire click, เตือนกระสุนใกล้หมด (ครั้งเดียวเมื่อข้ามเกณฑ์), รีโหลดไม่ได้เพราะกระสุนสำรองหมด (เสียงปฏิเสธสั้น ๆ + ข้อความบน HUD)

### 3.4 เสียงรีโหลด (ชุดต่อตระกูล)
- แม็กออก (โลหะเลื่อน + คลิก), จับปืน/เสียดสีผ้าและวัสดุ (เบากว่าเสียงหลัก), แม็กเข้า (คลิกชัดและหนักแน่น), ปล่อยสไลด์/โบลต์ (โลหะคม), เสียงยืนยันท้าย (กระชับ)
- โลหะคมแต่ไม่แหลมจัด ไม่มีเสียงแบบ UI ดิจิทัล แต่ละช่วงต่างทั้งเนื้อเสียงและความดัง แต่ฟังต่อเนื่องเป็นเหตุการณ์เดียว ไม่กลายเป็นเสียงคลิกซ้ำซาก
- เล่นจาก animation marker เท่านั้น ห้ามนำหน้าหรือช้ากว่าภาพ

### 3.5 กติกาซิงก์ภาพ–เสียง
เสียงหลักตรงกับเหตุการณ์ภาพ · เสียงย่อยไม่เล่นซ้ำเมื่อแอนิเมชันเปลี่ยนเฟรม · กันเสียงซ้อนจากการกดรัว · แยกเสียงเหตุการณ์หลักออกจากเสียงเบื้องหลัง · แอนิเมชันถูกขัด → หยุดหรือเปลี่ยนเสียงที่เกี่ยวข้อง · ห้ามมีเสียงค้างหลังเปลี่ยนสถานะ — เสียงกับภาพต้องรู้สึกเป็นระบบเดียวกัน

### 3.6 ฝีเท้าและการเคลื่อนไหว
- ฝีเท้าผู้เล่นและซอมบี้เปลี่ยนตาม surfaceType (คอนกรีต, กระเบื้อง, ไม้, หญ้า, ดิน/โคลน, น้ำ, โลหะ) ซิงก์กับจังหวะก้าวและ bob มีเสียงลงพื้นหลังกระโดด และวิ่งต่างจากเดิน
- ฝีเท้าซอมบี้เล่นเฉพาะตัวที่ใกล้ตาม voice limit ที่เหลือรวมเป็นเสียงฝูง

### 3.7 Environmental Acoustics (Audio Environment Zones)
ใส่ zone (กล่อง volume) ในข้อมูลแมพ ไม่ต้องมีไฟล์เสียงแยกต่อสถานการณ์:

| Zone | ใช้กับ | ลักษณะ |
|---|---|---|
| Indoor Corridor | ทางเดินโรงเรียน / โรงพยาบาล | สะท้อนแบบทางเดินแคบ หางพอดี ชัด ไม่ขุ่น |
| Underground Corridor | บังเกอร์ | สะท้อนผนังชัด หางต่อเนื่อง รู้สึกปิดและลึก |
| Small Enclosed Room | ห้องเรียน / ห้องน้ำ / ห้องเล็ก | สะท้อนสั้นและชัด ไม่ก้องยาว |
| Large Interior Room | หอประชุม / ห้องสมุด / โถง | หางยาวขึ้นตามขนาด กว้าง ไม่แห้ง |
| Large Warehouse | โกดัง / โรงจอด (ถ้ามี) | กว้าง มีระยะและปริมาตร ปรับตามตำแหน่งแหล่งเสียง |
| Outdoor | สนาม / สวน / ศาลา / หน้าโรงเรียน | ลดสะท้อนแบบห้องปิด หางกระจาย เสียงแวดล้อมเด่นขึ้น |

- Reverb ด้วย ConvolverNode + **impulse response ที่สร้างแบบ procedural ตอนโหลด** (ตั้ง RT60, pre-delay, damping, wet ต่อ zone)
- เปลี่ยน zone แบบ crossfade 0.5–1 วินาที ด้วย convolver 2 ตัวสลับกัน (A/B) ห้ามสร้าง convolver ใหม่ทุกครั้ง
- Very Low ไม่ใช้ convolution (ใช้ delay แบบง่ายหรือปิด)

### 3.8 Spatial Audio + Occlusion
- PannerNode: HRTF เฉพาะ High ขึ้นไปและเฉพาะเสียงใกล้จำนวนจำกัด นอกนั้นใช้ equalpower ความดังลดตามระยะอย่างเป็นธรรมชาติ listener ตามกล้อง **ห้ามแพนเสียงแบบสุ่มที่ไม่มีตำแหน่งจริงในโลกเกม**
- Occlusion: raycast จากผู้ฟังถึงแหล่งเสียง (ความถี่จำกัด เช่น 8 ครั้ง/วินาที เฉพาะ 8 แหล่งที่ใกล้ที่สุด) กับ collision แบบง่าย ถ้าถูกบัง → lowpass + ลดความดังแบบ interpolate 150–250 ms ห้ามตัดเสียงทันทีตอนเดินผ่านขอบผนัง ประตูเลื่อนเปิด/ปิดมีผล และรองรับการเปลี่ยนสภาพแวดล้อมต่อเนื่อง

### 3.9 Mixing priority
1) เหตุการณ์สำคัญที่ผู้เล่นต้องได้ยิน (ปืนผู้เล่น, บอสส่งสัญญาณ, โดนตี, HP ต่ำ) 2) การเคลื่อนไหวและกลไก 3) สิ่งแวดล้อม 4) เพลง — เสียงทุกชั้นต้องมีพื้นที่ของตัวเองในมิกซ์ และไม่ดังจนล้าหู

### 3.10 Sound Bank, Captions และการทดสอบ
- ไฟล์ sound bank (JSON): event → recipe แบบ procedural หรือรายการไฟล์ เพื่อให้เปลี่ยนเป็นไฟล์เสียงจริง (CC0) ภายหลังได้ (ใช้ .mp3/.m4a เพื่อให้ iPad เล่นได้แน่นอน และมีไฟล์ credits)
- **Sound Lab** (`?lab=sound`): ฟังทุก event ทุกปืน ทุก zone พร้อม meter ให้ผู้ใช้ทดสอบเองผ่านหูฟัง ลำโพง และ iPad
- **Captions (Subtitle Options)**: แสดงคำบรรยายเสียงสำคัญพร้อมทิศทาง (เช่น "[Screamer shrieks ←]", "[Bloater swelling]") ผ่าน i18n
- Settings เสียง: Master, Music, Weapons, SFX, Ambient, UI พร้อมปุ่มทดสอบเสียงข้างแต่ละ slider

### 4.2 กติกาศิลป์ (ทุกชนิดอยู่ในโลกศิลปะเดียวกัน)
- สไตล์ voxel-inspired, Minecraft-like blocky humanoid, stylized survival horror รูปทรงเรขาคณิตเหลี่ยมชัด แต่มีรายละเอียดใบหน้า เสื้อผ้า วัสดุ และท่าทางที่สร้างเอกลักษณ์
- **โครงร่าง**: หัวลูกบาศก์ ลำตัวสี่เหลี่ยม ไหล่กว้าง แขนขาเป็นแท่งเหลี่ยม มือเท้าเรียบง่าย สัดส่วนใกล้มนุษย์ในโลกบล็อก ปรับความกว้างไหล่ ความยาวแขน และขนาดหัวตามชนิด มีหลายรูปร่าง: ผอมโซ ปกติ อ้วน สูง กลายพันธุ์ ยืนยองเล็กน้อย แขนยื่นไปข้างหน้าเล็กน้อย
- **ไม่สมมาตร**: หัวเอียง ไหล่ตก ลำตัวโน้มหน้า แขนห้อยต่างระดับ เดินลากขา นิ้วขาด แขนงอ เสื้อผ้าขาด
- **ใบหน้า**: หน้าผากแบน คิ้วหนา เบ้าตาเข้ม จมูกเหลี่ยม ปากเป็น texture สีเข้ม หลายแบบ: ตากลวง ตาขาวขุ่น ตาเรืองแสง แก้มยุบ ฟันหัก ริมฝีปากฉีก แผลบนหน้า ผิวลอก สีผิว เขียวซีด เทาหม่น น้ำตาลซีด เทาอ่อน ฟกช้ำเข้ม **สีตาเป็นเอกลักษณ์ของแต่ละชนิด** (ตามตาราง) ตาบางชนิดเรืองแสงเบา ๆ ให้เห็นในที่มืด สีหน้าสื่ออารมณ์ เจ็บปวด งงงวย โกรธ หรือไร้วิญญาณ ไม่ใช่แค่ดุ ผมรุงรัง ร่วง หรือหายเป็นหย่อม
- **เสื้อผ้าเล่าอดีต**: พนักงานออฟฟิศ เกษตรกร (สายเอี๊ยม หมวก) ทหาร นักเรียน ช่างก่อสร้าง คนไร้บ้าน + **ชุดตามด่าน**: โรงเรียน = นักเรียน ครู ภารโรง / โรงพยาบาล = คนไข้ พยาบาล หมอ / บังเกอร์ = ทหาร ช่างเทคนิค ใช้โทนเสื้อดำ น้ำตาล เสื้อคลุมเข้ม แขนเสื้อแดง กางเกงเทาหรือน้ำเงินเข้ม มีกระดุม ขอบผ้า รอยซีด ลายพิกเซล ห้ามรายละเอียดสมจริงที่ขัดกับสไตล์บล็อก
- **Texture และ Shading**: pixel texture อ่านง่าย แบ่งกลุ่มสีชัด (เงา สีพื้น ไฮไลต์) ห้ามไล่สีนุ่มเกินไป ขอบรูปทรงคม
- **แสง**: ใช้ระบบแสง cinematic เดิม rim light ที่ขอบหัวและไหล่ เงาไม่ดำสนิท ตาเรืองแสงใช้ emissive (bloom บน High+) แต่ต้องไม่ทำให้ป้ายคำอ่านยาก
- **ความต่าง**: แยกด้วย silhouette ใบหน้า สีตา ชุด สัดส่วน ท่าทาง และวัสดุ — **ห้ามต่างกันแค่การเปลี่ยนสี** ซอมบี้คือมนุษย์ที่ติดเชื้อ ไม่ใช่มอนสเตอร์การ์ตูน สยองแบบกึ่งสมจริงแต่ไม่โหดเกินไป

### 4.3 ระบบสร้างซอมบี้ (ZombieFactory)
- ประกอบจากชิ้นส่วน: หัว (หลายทรง), ลำตัว (ผอม/ปกติ/อ้วน/สูง), แขน (ปกติ/ยาว/ขาด/งอ/นิ้วขาด), ขา (ปกติ/ลาก/ขาด), ผม, อุปกรณ์ (หมวก, หมวกกันน็อก, เสื้อเกราะ, กระเป๋า, เนกไท, สายเอี๊ยม, ป้ายชื่อ)
- texture วาดแบบ procedural ตอนโหลดลง **atlas เดียว** (canvas + NearestFilter) ไม่ต้องมีไฟล์ภาพจำนวนมาก และใช้ material ร่วมกันเพื่อลด draw calls
- สุ่มด้วย seed ต่อการเกิด ห้ามมีตัวที่หน้าตาเหมือนกันทุกจุดอยู่พร้อมกัน และแต่ละเวฟมีความหลากหลายขั้นต่ำตาม config
- เลือด แผล เนื้อฉีก กระดูกโผล่ คราบดิน เป็น pixel texture พอประมาณ + **ตั้งค่า Blood & Gore: Full / Reduced / Off** (Off = ไม่มีเลือด ใช้ฝุ่นเทาแทน และหัวหลุดเปลี่ยนเป็นควัน) **Runt ใช้แบบ Reduced เสมอ** (ไม่มีหัวหลุดหรือเลือดสาด ตายเป็นควัน)

### 4.4 แอนิเมชันซอมบี้ (animation state machine ต่อตัว, blend 0.1–0.25 วินาที)
- **Spawn**: ขุดขึ้นจากพื้น (ของเดิม)
- **Idle**: หยุดเป็นช่วง ๆ หันหัว โยกตัว
- **เดิน (Shambler)**: เซ ก้าวไม่สม่ำเสมอ ลากเท้าข้างหนึ่ง มีน้ำหนักเป็นจังหวะ
- **วิ่ง (Sprinter / Runt)**: เร็ว แขนสะบัดไปมา สมดุลไม่ดี สะดุดบ้าง
- **คลาน (Crawler)**: ใช้แขนข้างเดียวลากตัวไปข้างหน้า
- **Bloater**: เดินอุ้ยอ้าย ตอนตายบวมขึ้น 0.8–1.2 วินาที (ส่งสัญญาณทั้งภาพและเสียง) แล้วระเบิด
- **Screamer**: เงยหน้าตั้งท่า 1 วินาทีแล้วกรีดร้อง ถ้าฆ่าระหว่างตั้งท่า เสียงร้องจะถูกยกเลิก
- **Ironclad**: หมวกกระเด็นเมื่อโดนยิงหัวครบจำนวน (มีเสียงโลหะ)
- **Headless**: เดินประคองหัวใต้แขน หัวส่ายตามจังหวะ
- **Reacher**: ง้างแขนยาวก่อนฟาด ก้าวหนัก
- **โจมตี**: พุ่งเข้าคว้า กัด หรือฟาดแขน **ไม่ใช่ต่อยธรรมดา** และมีท่าเตรียมให้ผู้เล่นอ่านออก
- **โดนยิง** ตามระดับความเสียหาย: เบา = สะดุ้งแบบ additive / กลาง = เซถอย / หนัก = ล้มแล้วลุก ต้อง blend นุ่ม ไม่กระตุก และตรงกับสถานะของศัตรูใน gameplay
- **ตาย**: ร่างกลายเป็นควัน ส่วน headshot หัวหลุด (ของเดิม ตามค่า Blood & Gore)
- **Animation LOD**: ใกล้กว่า 15 m อัปเดตเต็ม / 15–30 m ครึ่งหนึ่ง / ไกลกว่า 30 m หนึ่งในสี่ / นอกจอไม่คำนวณท่า (ตำแหน่งยังเดินตามปกติ)

### 4.5 พฤติกรรม + กติกาคำศัพท์
- ซอมบี้ทุกชนิดยังมีป้ายคำและเล่นตามกติกาคำศัพท์เดิม — **ความสามารถพิเศษห้ามทำให้ข้ามการตอบคำศัพท์ได้**
  - Bloater ระเบิด: ทำดาเมจผู้เล่นในรัศมี และผลักหรือทำให้ซอมบี้ตัวอื่นเซ แต่ **ไม่ฆ่า** และไม่นับเป็นการตอบคำ
  - Screamer: ดึงความสนใจซอมบี้ที่มีอยู่ในรัศมีและเร่งความเร็วชั่วคราว ถ้าเรียกตัวใหม่ต้องนับรวมในโควตาเวฟ (ตัวนับบน HUD ต้องถูกต้อง) และมี cooldown
  - Ironclad: หมวกกันกระสุนเข้าหัวจนกว่าจะกระเด็น เกราะต้องไม่บังป้ายคำ
  - Headless: ป้ายคำอยู่เหนือหัวที่ถือ
  - Crawler: ตัวซ่อนในหญ้าได้ แต่ **ป้ายคำต้องอ่านได้เสมอ** (ตามกฎป้ายคำของระบบแสง)
  - Runt: hitbox เล็กลง แต่ป้ายคำขนาดเท่าเดิม
- ความรู้สึกเป็นฝูง: เมื่อหลายตัวเข้าใกล้ผู้เล่น ให้กระจายเป็นวงล้อม (ไม่เรียงแถวเดียว ใช้ pathfinding เดิม ห้ามเดินทะลุผนัง) + เสียงฝูงหนาขึ้น ให้อันตรายเพราะมาเป็นกลุ่ม ไม่ใช่แค่ตัวเดียว
- ตาราง spawn ต่อเวฟ (20 เวฟ + Endless) อยู่ใน zombie-config เวฟ 1 ยังช้าเหมือนเดิม Abomination มีได้ทีละ 1 ตัว เวฟบอส 5/10/15/20 ใช้ระบบเดิม
- รักษา fix เดิมเรื่อง hitbox ชัดเจนเมื่อซอมบี้ซ้อนกัน และปรับ hitbox (หัว / ตัว / แขนขา) ให้ตรงสัดส่วนใหม่ทุกชนิด

### 4.6 เสียงซอมบี้ (ใช้ระบบรอบ 3)
- แต่ละชนิดมีเสียงประจำตัว (คราง หายใจเสียงเปียก ติดขัด เสียงคลิก คำรามต่ำ) + เสียงตอบสนองสั้น ๆ เมื่อโดนยิง
  - Shambler: ครางแห้ง + ฝีเท้าถูพื้น · Sprinter: หายใจถี่ + ฝีเท้าเร็ว · Crawler: ขูดพื้น + ลากตัวเปียก ๆ · Bloater: หายใจหนัก เสียงเดือดในลำคอ เสียงภายในเปียก ๆ · Screamer: กรีดร้องแหลมสูงมีเสียงสะท้อน (คุมความดังสูงสุด ไม่บาดหู + caption) · Ironclad: โลหะกระทบตามก้าว · Headless: เสียงอู้อี้จากหัวที่ถือ · Reacher: ก้าวหนัก ลมหายใจต่ำ · Runt: เสียงแหลมสั้น ๆ · Abomination: คำรามซ้อนหลายชั้น
- ฝีเท้าตามพื้น: คอนกรีต หญ้า โคลน น้ำ โลหะ ฯลฯ
- แยกเสียงใกล้และไกล (ไกล = lowpass + reverb มากขึ้น) จำกัดจำนวน ไม่กลบเสียงสำคัญ และมี **horde bed** ซ้อนเสียงครางกับเสียงเดินตามจำนวนซอมบี้ใกล้ ๆ
- สร้างแบบ procedural (formant filter + noise + oscillator) ผ่าน sound bank ซึ่งเปลี่ยนเป็นไฟล์จริงภายหลังได้

### 4.7 บอส
ปรับโมเดลบอสทั้ง 10 ตัวให้เข้ากับกติกาศิลป์เดียวกัน **แต่คงชื่อ รูปลักษณ์เฉพาะ พลัง และ cutscene เดิมไว้ทั้งหมด**

### 4.8 ประสิทธิภาพ
material และ atlas ร่วมกัน, merge geometry ต่อชิ้นส่วน, InstancedMesh เมื่อเหมาะ, จำนวนซอมบี้สูงสุดพร้อมกันตาม tier

### เกณฑ์ผ่านรอบ 4
- **Zombie Gallery** (`?lab=zombies`): แสดงทั้ง 10 ชนิด × 3 รูปแบบสุ่ม ทั้งมุมหน้าตรงและมุมสามส่วน (three-quarter view) เล่นแอนิเมชันทุกท่าได้ แล้วเซฟภาพรวมเป็น `docs/overhaul/zombie-sheet.png`
- iPad Medium ≥ 30 FPS ในเวฟที่ซอมบี้เยอะที่สุด

## รอบ 5 — หน้าเมนูหลักใหม่ (แทนหน้า Tap To Lobby)

### 5.1 Flow
Loading screen (เดิม) → **Main Menu ใหม่** → กด PLAY → **Lobby เดิม** (เลือกด่าน/carousel เหมือนเดิม + เพิ่มปุ่มกลับ Main Menu)
- เอาหน้า Tap To Lobby ออก แต่ย้ายงานที่หน้านั้นเคยทำ (ปลดล็อกเสียง, fullscreen, เช็กอัปเดต ฯลฯ) มาไว้ที่ interaction แรกหรือปุ่ม PLAY
- ก่อนผู้ใช้แตะครั้งแรก เบราว์เซอร์ยังไม่ให้เล่นเสียง → แสดงไอคอนเล็ก "Click / Tap to enable sound" ที่มุมจอ แล้วค่อย fade เพลงเข้าหลังแตะ
- ถ้ามีแถบ UID แบบโปร่งอยู่แล้ว ให้ย้ายมาไว้มุมล่างของหน้านี้ (ระบบบัญชียังพักไว้ ห้ามสร้างตอนนี้) และแสดงเลขเวอร์ชันเล็ก ๆ
- การแจ้งอัปเดตจาก version.json ยังต้องแสดงในหน้านี้

### 5.2 เมนูซ้าย (ย้ายมาจากลอบบี้)
**PLAY** (ในสเปกเขียน "PLAY TO LOBBY" — กดแล้วไปหน้า Lobby) · PROGRESS · VOCAB · NOTES · CUSTOM · WEAPONS · BOSSES · RANKS · AWARDS · SETTINGS · HELP
- จัดกลุ่มด้วยเส้นคั่นบาง ๆ: เล่น / เรียนรู้ / สะสม / ระบบ
- ถ้าลอบบี้มีเมนูอื่นอีก (เช่น Daily Review พร้อม badge จำนวนคำที่ถึงกำหนด) ให้ย้ายมาด้วย
- แต่ละปุ่มเปิดหน้าเดิมที่มีอยู่แล้ว ไม่ต้องเขียนเนื้อหาใหม่

### 5.3 คอนเซปต์และอารมณ์
หน้าล็อบบี้หลักของเกม 3D แนว Zombie Survival / Post-Apocalyptic Horror ให้อารมณ์เหมือน Main Menu ของเกมเอาชีวิตรอดในฐานใต้ดินที่ถูกทิ้งร้าง: Dark Survival Horror · Abandoned Underground Facility · Zombie Outbreak Atmosphere · Industrial Sci-Fi · Tactical Survival · Cinematic Environmental Storytelling · Low-Key Lighting · Subtle Ambient Animation · Minimalist Functional UI
- ต้องรู้สึกว่าโลกในเกมกำลังดำเนินอยู่หลังเมนู ผู้เล่นกำลังมองเข้าไปในสถานที่จริง ไม่ใช่ภาพนิ่ง
- **ห้าม** เมนูแฟนตาซีสีสด ห้ามพื้นหลังสีเรียบ และหลีกเลี่ยงปุ่มใหญ่จำนวนมากแบบเกมมือถือ

### 5.4 ฉากหลัง (3D จริง สไตล์ voxel/บล็อก)
ทางเดินอุตสาหกรรมของฐานใต้ดิน/สถานกักกันเชื้อ ยาวลึกเข้าไปในฉาก · ผนังคอนกรีตเก่า ผนังโลหะ โครงเหล็ก · ท่อหลายขนาดตามผนังและเพดาน · สายไฟห้อยหรือเดินตามโครงสร้าง · **ประตูเหล็กขนาดใหญ่กลางฉาก** · แผงควบคุมและไฟสถานะเล็ก ๆ ตามผนัง · พื้นโลหะหรือคอนกรีตมีร่องรอยใช้งาน · กล่องอุปกรณ์และวัตถุภาคสนามบริเวณขอบฉาก · พื้นที่มืดลึกด้านหลังที่เห็นรายละเอียดได้บางส่วน
- Perspective ชัด: เส้นพื้น ผนัง เพดาน และท่อ พาสายตาเข้าสู่ประตูกลาง
- รายละเอียดพอเมื่อมองใกล้ แต่ไม่แย่งความสนใจจากโลโก้ ตัวละคร และเมนู

### 5.5 แสงและสี (Low-Key Cinematic Lighting)
- สี (ค่าแนะนำ): Near Black `#0B0C0E` · Charcoal Grey `#2A2D31` · Dark Industrial Brown `#3B2F26` · Muted Military Green `#4A5A3F` · Teal/Cyan Accent `#3FC1B0` · Deep Red Emergency `#A3161F` · Warm Orange Doorway `#FF8A3D`
- ขอบจอมืดกว่ากลางฉาก · ไฟแดง/ส้มเหนือประตูเหล็กเป็นจุดสนใจหลัก · ไฟเขียวอมฟ้าอ่อน ๆ จากด้านข้างแยกรูปร่างตัวละครจากความมืด · เงาทอดจากท่อ โครงเหล็ก และอุปกรณ์บนผนัง · Ambient Occlusion ตามรอยต่อและมุม (baked vertex AO + SSAO บน High+) · Volumetric fog บาง ๆ เฉพาะบริเวณที่มีลำแสง (ทำแบบ fake light shaft ราคาถูก) · หลีกเลี่ยงแสงสว่างทั่วฉาก
- ไฟบางดวงกะพริบช้าและไม่สม่ำเสมอได้ แต่ห้ามกะพริบทั้งฉากหรือสว่างวาบรุนแรง

### 5.6 โลโก้
- ใช้ชื่อเกมจริง: **VOCAB ZOMBIE** (ตัวหลัก สีขาวสลับแดงเข้ม) และ **IELTS SURVIVAL** ขนาดเล็กกว่าอยู่ใต้ชื่อหลัก (ชื่อ "OUTBREAK SERVER" ในสเปกเป็นแค่ตัวอย่าง)
- ฟอนต์ Bold Condensed Display ที่ใช้ได้ฟรี (OFL) เก็บไฟล์ในโปรเจกต์ + cache ใน service worker พื้นผิวหยาบเล็กน้อยให้ความรู้สึกผ่านการใช้งาน เงาบาง ๆ และขอบที่อ่านชัด
- วางกึ่งกลางด้านบน มีพื้นที่ว่างรอบโลโก้ ห้ามบังหัวตัวละครหรือรายละเอียดสำคัญของประตู ทำเป็น SVG/HTML overlay ให้คมทุกความละเอียด และต้องดูเป็นอัตลักษณ์ของเกม ไม่ใช่ข้อความทั่วไปที่วางทับภาพ

### 5.7 ตัวละครผู้รอดชีวิต 3D (ด้านขวาของจอ)
- ตัวละคร voxel ทรงเหลี่ยม (ต่อยอดจากโมเดลผู้เล่นเดิม) ชุดภาคสนามโทนเข้ม เสื้อคลุมหรือเกราะเรียบง่าย สายรัด กระเป๋า อุปกรณ์เอาตัวรอดเล็ก ๆ สีดำ เทาเข้ม เขียวหม่น น้ำตาลเข้ม รอยสึกพอเหมาะ ใบหน้าบางส่วนอยู่ในเงา rim light เขียวอมฟ้าที่ขอบหัว ไหล่ และลำตัว มีเงาตกกระทบพื้นและแสงสะท้อนจากสิ่งแวดล้อม — ต้องเป็นโมเดล 3D จริง ไม่ใช่ภาพ 2D วางบนฉาก
- **Idle loop** (ใช้ animation state machine): ลำตัวขึ้นลงตามจังหวะหายใจ, ไหล่และหัวขยับละเอียด, หันมองประตูหรือความมืดเป็นครั้งคราว, แขนและมือขยับเล็กน้อย, อุปกรณ์ติดตัวขยับตามแรงเฉื่อย, เปลี่ยนท่ายืนเป็นครั้งคราวแบบไม่ฉับพลัน — ห้ามกระตุกหรือเห็นรอยต่อ loop ให้รู้สึกว่ากำลัง "เฝ้าระวังในที่อันตราย" ไม่ใช่ "โพสท่าถ่ายรูป"

### 5.8 เมนูและการตอบสนอง
- แผงสี่เหลี่ยมกะทัดรัด ไม่บังตัวละครและประตูหลัก พื้นดำหรือเขียวเข้มโปร่งแสง (`rgba(8,14,10,0.72)`) ขอบเขียวหม่น (`#5E7A55`) ตัวอักษรเล็กอ่านง่าย ระยะห่างสม่ำเสมอ กรอบเหลี่ยมแทนปุ่มกลม เส้นแดงบาง ๆ (`#B3262E`) บางจุดเชื่อมกับธีมการระบาด
- **Hover**: ขอบสว่างขึ้น (`#9BC48A`) พื้นเขียวเข้มขึ้นเล็กน้อย ตัวอักษรสว่างขึ้น transition สั้นและนุ่ม + เสียงคลิกเบา ๆ **ครั้งเดียวต่อการเข้าปุ่ม** (ไม่ดังทุกเฟรม)
- **Selected**: สถานะชัด แสงขอบหรือเส้นเน้นสีเขียว + เสียง UI click สั้น ๆ เปิดหน้าต่างใหม่ใช้ fade หรือ slide ที่รวดเร็ว
- รองรับ mouse, keyboard (ลูกศร / Enter / Esc), controller (D-pad หรือ stick, A / B) และ touch (แตะเลือก พื้นที่กดอย่างน้อย 44 px แต่หน้าตายังกะทัดรัด และไม่มีเสียง hover บน touch)

### 5.9 ความเคลื่อนไหวของฉาก (ขยับตลอดแม้ไม่กดอะไร)
ไฟเตือนแดงกะพริบเป็นจังหวะช้า · หลอดไฟเปลี่ยนความเข้มเล็กน้อย · หมอกบางเคลื่อนผ่านลำแสง · ฝุ่นลอยผ่านลำแสง · พัดลมหรือเครื่องจักรหมุนช้า · เงาในที่ลึกเปลี่ยนละเอียด · ตัวละครเล่น idle · กล้อง sway / parallax ช้า ๆ ระยะสั้น (ปิดเมื่อเปิด Reduce Motion)
ความเคลื่อนไหวต้องไม่สม่ำเสมอจนดูเหมือนภาพนิ่ง แต่ไม่มีการเคลื่อนไหวใหญ่ที่รบกวนการอ่านเมนู ห้ามหมุนกล้องรอบฉากอย่างรวดเร็ว

### 5.10 เสียง (ใช้ mixer จากรอบ 3)
- **เพลง**: ambient horror แบบ generative (สร้างด้วยโค้ด) — drone ความถี่ต่ำ เบสลึกยาว เสียงสังเคราะห์ที่ไม่แน่นอน โน้ตห่าง ๆ ที่โดดเดี่ยว ช่วงเงียบให้เสียงสิ่งแวดล้อม ไม่มีกลองหนักหรือเร็วตลอดเวลา เบากว่าเสียง UI และต่อเนื่องไม่มีเสียงกระโดดเมื่อวน
- **บรรยากาศใต้ดิน**: เครื่องระบายอากาศไกล ๆ ไฟฟ้าฮัมเบา ๆ โลหะสั่นเป็นครั้งคราว เครื่องจักรหลังผนัง ลมผ่านทางเดิน เสียงกระทบจากที่มืดเป็นครั้งคราว — ทุกเสียงมีตำแหน่งจริงในฉาก (stereo panning ตามตำแหน่ง ระยะ) ไกล = เบาและทึบกว่า พร้อม reverb แบบใต้ดิน
- **UI**: Hover (คลิกอิเล็กทรอนิกส์เบา สั้น) · Select (ยืนยันหนักขึ้นเล็กน้อย อาจผสมเสียงสวิตช์) · Open Menu (ยืนยันสั้น ไม่แหลม) · Back/Close (สั้นและต่างจาก Open ให้รู้ทันทีว่าย้อนกลับ)
- **ตัวละคร**: เสียงผ้าหรืออุปกรณ์เสียดสีเบามากเป็นครั้งคราว ไม่ต้องดังทุกครั้งที่ขยับ
- เพลงเป็นชั้นหลักที่เบาและต่อเนื่อง บรรยากาศสร้างมิติ UI ชัดและตอบสนองทันที ไม่แย่งความสนใจกัน **ห้ามเสียงตกใจดังฉับพลันซ้ำ ๆ ในหน้าเมนู** ปรับ Music / SFX / Ambient แยกกันได้ เพลงและบรรยากาศต่อเนื่องระหว่างหน้าเมนู แล้ว fade เข้าสู่ลอบบี้หรือเกม

### 5.11 กล้องและองค์ประกอบ
- Cinematic Fixed Menu Camera มองตามแนวทางเดิน: ประตูหลักกลางฉาก · โลโก้ด้านบน · เมนูซ้าย · ตัวละครขวา · วัตถุประกอบที่มุมล่างเพิ่มความลึก · UI ไม่บังตัวละคร · เว้นพื้นที่มืดให้ตัวอักษรอ่านง่าย
- Depth of Field เล็กน้อยเฉพาะ High+ ฉากหลังยังเห็นโครงสร้างสำคัญชัด ไม่เบลอทั้งฉาก
- สมดุลทั้ง 16:9, 4:3 (iPad), 19.5:9 และ 21:9 โดยปรับกล้องและตำแหน่งตามอัตราส่วน แนวตั้งแสดงคำแนะนำให้หมุนจอหรือจัดแบบซ้อน

### 5.12 สถานะและ Transition
- Main Menu: ฉากหลัง + ตัวละคร + โลโก้ + เมนู
- Settings: เปิดเป็นแผงทับฉากโดยไม่ทำลายฉาก ลดความเด่นของเมนูด้านหลัง แสดงทุกหมวดเดิม (กราฟิก เสียง การควบคุม ภาษา HUD Accessibility ฯลฯ)
- Transition: fade / slide / scale เล็กน้อย ห้ามกะพริบจอแรง เพลงและบรรยากาศต่อเนื่องระหว่างเปลี่ยนหน้า
- UI state manager กันการเปิดหน้าต่างซ้อนผิดพลาด (ใช้ระบบ modal/panel กลาง)

### 5.13 เทคนิคและประสิทธิภาพ
- 3D scene จริง, material และแสงตาม tier, LOD, merge geometry
- โหลด asset ของเมนูก่อน แล้วโหลดของ gameplay ต่อเบื้องหลัง

### 6.2 องค์ประกอบและข้อมูล (ทุกค่าอ่านจาก Game State)
- **Savings**: เงินในรอบเล่นปัจจุบัน (ระบบเงินเดิม) ตัวอักษรขาวขนาดใหญ่พออ่านง่าย เว้นระยะจากขอบจอและองค์ประกอบอื่น รูปแบบ "Savings 0$" ผ่าน i18n

- Game Over / เริ่มใหม่ / เปลี่ยนด่าน → ล้างค่าทั้งหมดแล้วอ่านจาก state ใหม่

## รอบ 7 — อธิบายคำตอบทุกคำถาม (ผิด → ทำไมผิด / ถูก → อธิบายด้วย)

### 7.1 ครอบคลุมทุกจุดที่มีคำถาม
การยิงคำระหว่างเวฟ, quiz บอสและ combo, quiz 6 ข้อท้ายเวฟ, คำถามหลังฆ่าบอส (ability รวงผึ้ง), ประตูคำศัพท์และการปลดล็อกชั้น, Daily Review, คำถาม 8 แบบ (รวมรูปคำและ POS), โหมด Spelling / Dictation / Listening / Paraphrase / Context และคำศัพท์ custom

### 7.2 เนื้อหาคำอธิบาย (สั้นและเข้าใจง่าย)
**ตอบผิด**
1. ✗ สิ่งที่เลือก: คำ + POS + ความหมาย
2. ✓ คำตอบที่ถูก: คำ + POS + ความหมาย
3. **ทำไมผิด** 1–2 ประโยค ตามสาเหตุ: ความหมายต่างกัน · คำที่สับสนง่าย (สะกดหรือเสียงคล้าย) · ผิดชนิดคำ (POS) · ผิดรูปคำ (word form) · สะกดผิด (ไฮไลต์ตัวอักษรที่ต่าง) · collocation ไม่เข้ากัน · ไม่เข้ากับบริบทประโยค
4. ตัวอย่างประโยคของคำที่ถูก + คำแปล
5. (ถ้ามี) เคล็ดลับจำ หรือข้อผิดพลาดที่พบบ่อยในข้อสอบ IELTS

**ตอบถูก**: ✓ คำ + POS + ความหมาย + ตัวอย่างหรือ collocation 1 อย่าง + (ถ้ามี) คำในตระกูลเดียวกัน

ตัวอย่างระดับรายละเอียดที่ต้องการ (ตัวอย่างประกอบ เขียนตามแนวนี้):

> ✗ คุณเลือก **provide** (V.) = จัดหาให้
> ✓ คำที่ถูกคือ **consist of** (V.) = ประกอบด้วย
> ทำไมผิด: provide แปลว่า "ให้หรือจัดหาสิ่งของให้ใคร" ไม่ได้บอกว่าอะไรเป็นส่วนประกอบของอะไร
> ตัวอย่าง: The team **consists of** five students. = ทีมประกอบด้วยนักเรียนห้าคน
> เคล็ดลับ: consist of ไม่ใช้รูป passive — ห้ามเขียน "is consisted of"

> ✗ คุณสะกด **recieve** → ✓ **receive** (V.) = ได้รับ
> จุดที่ผิด: rec**ie**ve → rec**ei**ve (หลังตัว c ใช้ ei)

> ✓ ถูกต้อง! **reciprocal** (Adj.) = ซึ่งกันและกัน, ตอบแทนกัน — a reciprocal agreement = ข้อตกลงที่ต่างฝ่ายต่างให้ประโยชน์แก่กัน

### 7.3 ข้อมูล
- ประกอบจากฟิลด์เดิมใน Master Word Bank (headword, partOfSpeech, ความหมาย 4 ภาษา, definition, examples, collocations, family, confusables, commonMisspellings, synonyms, paraphrase)
- เพิ่มฟิลด์ใหม่เฉพาะที่จำเป็น: `explain` (หมายเหตุสั้นต่อคำ ต่อภาษา) และ `confusableNotes` (อธิบายคู่คำที่สับสนและการสะกดผิดที่พบบ่อย)
- เขียนเนื้อหาไว้ล่วงหน้าตอนพัฒนา (offline) ตอนเล่นไม่เรียก AI หรืออินเทอร์เน็ต คู่คำที่ไม่มีคำอธิบายเฉพาะให้ใช้ template จากข้อมูล (POS ต่าง, ความหมายต่าง, ความคล้ายของการสะกดด้วย edit distance)
- ภาษาคำอธิบาย = **Meaning Language** ที่ผู้เล่นตั้งไว้ (fallback เป็นภาษา UI) ตัวอย่างประโยคใช้ Word Language + คำแปล และภาษาอังกฤษในตัวอย่างต้องถูกไวยากรณ์ 100%
- ขยาย validate-words script ให้รายงาน % ความครอบคลุมของคำอธิบายต่อภาษา และรายการคำหรือคู่คำที่ยังใช้ template

### 7.4 UX
- **คำถามที่หยุดเกมอยู่แล้ว (popup/modal)**: หลังตอบ แสดงคำอธิบายในหน้าต่างเดิม → ปุ่ม Continue (Enter / Space / A / แตะ) timer หยุดระหว่างอ่าน ปิด hotkey 1–4 ระหว่างแสดงคำอธิบายเพื่อกันการกดตอบซ้ำ ค่าเริ่มต้นเป็นแบบย่อ กด More เพื่อดูแบบเต็ม
- **คำถามแบบเรียลไทม์ (ยิงคำระหว่างเวฟ)**: ไม่หยุดเกม แสดงการ์ดสั้นใต้กล่องคำถาม (ไม่ทับ combo หรือแถบ HP บอส) — ผิด: "✗ provide = จัดหาให้ · ✓ consist of = ประกอบด้วย" 3–4 วินาที / ถูก: "✓ consist of (V.) = ประกอบด้วย" 2 วินาที ถ้ายิงผิดรัว ๆ ให้รวมการ์ด และนับเฉพาะกระสุนที่โดนซอมบี้ที่มีป้ายคำ
- **Review ท้ายเวฟ** (ตอนเกมหยุด): รายการคำของเวฟนั้น คำที่ผิดขึ้นก่อนพร้อมคำอธิบายเต็ม ตามด้วยคำที่ถูกแบบย่อ (กดขยายได้)
- Vocab log / Progress เก็บประวัติ "ผิดเพราะอะไร" ต่อคำ และเพิ่มเข้า personal confusion pairs เดิม
- Settings: รายละเอียดคำอธิบาย (Short / Full), Auto-continue หลังตอบถูก (Off / 2s / 4s), การ์ดคำอธิบายระหว่างต่อสู้ (On / Off)
- การอ่านคำอธิบายไม่เปลี่ยนกล่อง SRS (ใช้กติกา SRS เดิม) และปุ่มลำโพงอ่านคำและประโยคตัวอย่างได้

### เกณฑ์ผ่านรอบ 7
ทุกประเภทคำถามแสดงคำอธิบายทั้งกรณีถูกและผิด (มี test อัตโนมัติ) + สุ่มตรวจคำอธิบาย 40 ข้อเองแล้วลิสต์ไว้ในสรุปให้ผู้ใช้ตรวจซ้ำ (เนื้อหาที่ AI เขียนต้องมีคนตรวจ) พร้อมระบุข้อที่ไม่แน่ใจ

### Test Checklist (อัตโนมัติเมื่อทำได้ + เช็กลิสต์ให้ผู้ใช้ทดสอบบน iPad)
- **Animation**: เปลี่ยนสถานะไม่กระตุก · มือไม่ทะลุโมเดล · ปืนไม่หลุดตำแหน่งจากกล้อง · กลับสู่สถานะปกติได้ · ยกเลิกแอนิเมชันไม่ทำให้ระบบค้าง · ซอมบี้ blend ท่านุ่ม
- **Audio**: เสียงตรงกับแอนิเมชัน · ไม่มีเสียงซ้ำจาก event เดียวกัน · ไม่มีเสียงค้างหลังเปลี่ยนสถานะ · reverb เหมาะกับพื้นที่ · ระดับเสียงไม่กลบเสียงสำคัญ · ไม่มี clipping
- **Gameplay**: UI ตรงกับข้อมูลจริง · สถานะเกมเพลย์ไม่ขึ้นกับภาพแอนิเมชันอย่างเดียว · สลับอาวุธไม่ทำให้สถานะผิด · หยุดและเล่นต่อได้ทุกจุด · เหตุการณ์เกิดพร้อมกันหลายอย่างได้ · ความสามารถซอมบี้ไม่ข้ามกติกาคำศัพท์
- **UI**: เมนูหลักและ HUD ไม่ทับกันทุกอัตราส่วน · keyboard / controller / touch ใช้ได้ทุกหน้า · i18n ครบ 4 ภาษา (ไม่มี key ค้าง)
- **Explanations**: ทุกประเภทคำถาม ทั้งถูกและผิด
- **Performance**: frame time, memory, จำนวน particle, จำนวนเสียงพร้อมกัน, draw calls ในฉากที่มีซอมบี้และเอฟเฟกต์จำนวนมาก (stress test)

1. ทำอะไรไปแล้ว แยกตามหัวข้อ + ไฟล์ที่แก้หรือสร้าง

4. การตัดสินใจและสมมติฐานที่ใช้
5. บั๊กที่เจอและแก้แล้ว / ที่ยังเหลือ
