# Vocab Zombie: IELTS Survival — ส่วนขยาย 7 ระบบ
## ค่าพลังปืน · โต๊ะอัปเกรดด้วยคำศัพท์ · อุปกรณ์เสริมและสกิน · อาวุธระยะประชิด · ด่านสอนเล่น · เซฟสำรองและบัญชีผู้ใช้ · รายงานบั๊ก

### บทบาท
คุณคือ Senior Game Developer (Three.js/Web), Gameplay & Balance Designer, Learning Experience Designer, Sound Designer (Web Audio API), UI/UX Designer และ Web Backend/Security Engineer ที่ทำงานกับโปรเจกต์ "Vocab Zombie: IELTS Survival" ซึ่งมีอยู่แล้ว งานนี้คือการเพิ่มระบบใหม่ให้เชื่อมกับระบบเดิม ไม่ใช่สร้างเกมใหม่

### ขอบเขต 7 ระบบ
1. **ตารางค่าพลังปืน (stat sheet)** — ข้อมูลกลางของปืนทุกกระบอก เครื่องมือ balance และการ์ดค่าพลังในเกม
2. **โต๊ะอัปเกรดด้วยคำศัพท์ (Word Forge)** — อัปเกรดปืน 3 ขั้น โดยต้องตอบคำยากหรือคำที่เคยตอบผิด
3. **อุปกรณ์เสริมและสกินปืน** — ปลดล็อกจากความคืบหน้าการเรียน และมีตระกูลเสียงปืนเก็บเสียงเพิ่ม
4. **อาวุธระยะประชิดหลายแบบ** — มีด ไม้เบสบอล มีดพร้า ขวานดับเพลิง ชะแลง พลั่วสนาม
5. **ด่านสอนเล่น + คำแนะนำตามสถานการณ์**
6. **เซฟสำรองและบัญชีผู้ใช้** — ส่งออก/นำเข้าเซฟ สำรองอัตโนมัติ บัญชีผู้ใช้ UID โปรไฟล์ และซิงก์ขึ้นคลาวด์
7. **ปุ่มรายงานบั๊กและรายงานคำศัพท์ในเกม**

### ความสัมพันธ์กับงานก่อนหน้า
- ถ้ามี `docs/overhaul/PROMPT.md` (prompt การปรับเปลี่ยนครั้งใหญ่) ให้ใช้กฎทั่วไปทุกข้อในไฟล์นั้นด้วย
- **รอบ 1–2 ของ prompt นี้ทำได้ทันที** แม้ overhaul ยังไม่เสร็จ เพราะไม่ขึ้นกับระบบใหม่ และช่วยกันข้อมูลหายกับช่วยหาบั๊กของทุกรอบที่ตามมา
- รอบ 3–5 ต้องรอให้ overhaul รอบ 1–3 เสร็จก่อน (Weapon State Machine, รูปลักษณ์ปืน, ระบบเสียง)
- รอบ 6–7 ต้องรอ overhaul รอบ 5–7 ด้วย (เมนูหลัก, HUD, คำอธิบายคำตอบ) ถ้ายังไม่เสร็จ ให้หยุดแจ้งผู้ใช้
- ในรอบ 1–2 ถ้ายังไม่มี Event Bus หรือ Weapon State Machine ให้เก็บข้อมูลเท่าที่มี แล้วเพิ่มส่วนที่ขาดเมื่อระบบเหล่านั้นเสร็จ
- ถ้ามี `docs/reference/guns/GUN_REFERENCE.md` (ข้อมูลอ้างอิงปืนจากวิดีโอ) ให้ใช้ตระกูลปืน พาเลตสี และสูตรเสียงจากไฟล์นั้น

### ลำดับรอบ
รอบ 0 สำรวจ + แผน → รอบ 1 เซฟสำรอง/ส่งออก/นำเข้า → รอบ 2 รายงานบั๊กและรายงานคำศัพท์ → รอบ 3 ค่าพลังปืน → รอบ 4 อาวุธระยะประชิด → รอบ 5 อุปกรณ์เสริมและสกิน → รอบ 6 Word Forge → รอบ 7 ด่านสอนเล่น → รอบ 8 บัญชีผู้ใช้และคลาวด์ → รอบ 9 ทดสอบรวม + deploy

## กฎทั่วไป (ใช้ทุกรอบ)
1. **อ่านโค้ดจริงก่อนลงมือ** — หากมีระบบเดิมอยู่แล้ว ให้ตรวจสอบระบบเดิมก่อนสร้างใหม่ และหลีกเลี่ยงการเขียนทับโค้ดหรือไฟล์ที่ไม่เกี่ยวข้อง
2. **ห้ามแต่ง API** — ใช้เฉพาะ API ที่มีจริงใน Three.js เวอร์ชันที่โปรเจกต์ใช้, Web API มาตรฐาน และ Firebase Web SDK เวอร์ชันที่ติดตั้ง ถ้าไม่แน่ใจให้ตรวจเอกสารก่อน สมมติฐานที่ใช้ให้เขียนไว้ในสรุป
3. **ห้ามลบหรือทำฟีเจอร์เดิมพัง** (perk, บอส, ability, SRS/Daily Review, 4 ภาษา, ปุ่ม touch, quality tiers, checkpoint เวฟ 10, mystery box, ปืนติดผนัง, story notes, update flow ฯลฯ) ถ้าต้องเปลี่ยนพฤติกรรม ให้แจ้งในสรุป
4. **ข้อมูลขับเคลื่อนทั้งหมด** — ค่าพลัง เงื่อนไขปลดล็อก ราคา และเวลาแอนิเมชัน อยู่ในไฟล์ data/config ไม่ฝังในโค้ด ตัวเลขใน prompt นี้เป็น "ค่าเริ่มต้นแนะนำ"
5. **ข้อความใหม่ทุกตัวผ่าน i18n ครบ 4 ภาษา** และ popup ทุกอันใช้ openModal/closeModal กลาง
6. **ทุกฟีเจอร์ต้องใช้ได้ทั้ง keyboard/mouse, controller และ touch บน iPad**
7. **ทุกกติกาต้องเคารพกติกาคำศัพท์เดิม** — ความสามารถหรือดาเมจพิเศษห้ามทำให้ข้ามการตอบคำได้ และการตอบคำทุกครั้งต้องเป็นไปตามกฎ SRS เดิม (คำใบ้ = ไม่เปลี่ยนกล่อง, กล่อง 4–5 ต้องใช้งานแบบนึกคำเอง, คำใหม่ไม่เกิน 4 คำต่อเวฟ)
8. **ประสิทธิภาพ**: desktop High ≥ 60 FPS และ iPad Medium ≥ 30 FPS ต้องคงอยู่หลังเพิ่มทุกระบบ
9. **ความเป็นส่วนตัว**: เก็บข้อมูลส่วนบุคคลให้น้อยที่สุด ห้ามบันทึกโทเคนหรือรหัสผ่านเอง
10. **ทำทีละรอบ**: จบแต่ละรอบให้ตรวจบั๊ก → แก้ทันที → อัปเดต `docs/expansion/progress.md` → commit → สรุปผล แล้วไปรอบถัดไป ถ้ายังไม่มีไฟล์ prompt นี้ใน repo ให้บันทึกไว้ที่ `docs/expansion/PROMPT.md`

## รอบ 1 — เซฟสำรอง ส่งออก และนำเข้า (ทำได้ทันที)

### 1.1 SaveManager กลาง
- **schema เดียวมี `schemaVersion`** แบ่งหมวด:
  - `profile` — ชื่อ, avatar, publicId (ถ้ามี)
  - `settings` — ภาษา, accessibility, HUD, ผังปุ่ม touch, คุณภาพกราฟิก, เสียง
  - `learning` — SRS ทุกคำ, สถิติคำ, confusion pairs, คำศัพท์ custom, streak ของ Daily Review, ประวัติ "ผิดเพราะอะไร"
  - `progress` — ด่าน/ชั้นที่ปลดล็อก, story notes, awards, ranks, บอสที่เคยเจอ, weapon log, อุปกรณ์เสริมและสกินที่ปลดล็อก
  - `checkpoint` — สถานะเวฟ 10 ของแต่ละด่าน (ตามระบบเดิม)
  - `flags` — สถานะด่านสอนเล่น, tips ที่เคยแสดง
  - `meta` — createdAt, updatedAt, deviceId, gameVersion, เวลาเล่นรวม
- เขียน schema ลง `docs/expansion/save-schema.md`
- **ที่เก็บ**: IndexedDB เป็นหลัก ถ้าใช้ไม่ได้ให้ fallback เป็น localStorage
  - เขียนแบบ atomic (transaction เดียว หรือเขียนคีย์ชั่วคราวแล้วสลับ)
  - debounce ≥ 2 วินาที และบังคับเขียนทันทีตอน `visibilitychange` (hidden) / `pagehide`
- เรียก `navigator.storage.persist()` ถ้าเบราว์เซอร์รองรับ และแสดงสถานะการเก็บข้อมูลในหน้า Settings → Data
- **Migration**: ฟังก์ชันแปลงเรียงตามเวอร์ชัน (v1→v2→…) พร้อม unit test จาก fixture ถ้า migration ล้มเหลว **ห้ามทับข้อมูลเดิม** ให้เก็บต้นฉบับไว้ แสดงข้อผิดพลาด และให้ผู้เล่นส่งออกข้อมูลดิบได้

### 1.2 สำรองอัตโนมัติ
- เก็บ snapshot ใน IndexedDB สูงสุด 7 ชุด: รายวัน + ก่อนการกระทำเสี่ยง (นำเข้า, migration, เชื่อมบัญชี, merge, รีเซ็ต)
- Settings → Data → "Backups" แสดงวันที่และสรุป (จำนวนคำที่จำได้, เวลาเล่น, ด่านที่ปลดล็อก) → กู้คืนได้ (ยืนยันก่อน และ snapshot สถานะปัจจุบันไว้ก่อนเสมอ)

### 1.3 ส่งออก (Export)
- ไฟล์ `vocab-zombie-save-YYYYMMDD-HHMM.vzsave` เป็น JSON มี header `{app, schemaVersion, gameVersion, exportedAt, deviceLabel, checksum SHA-256 ของ payload}` + payload
- บีบอัดด้วย `CompressionStream` ถ้ารองรับ และบันทึก flag ไว้ใน header
- iPad: ใช้ Web Share (`navigator.canShare({files})`) เพื่อ "บันทึกไปยังไฟล์" ถ้าไม่รองรับให้ดาวน์โหลด · PC: ดาวน์โหลด

### 1.4 นำเข้า (Import)
- เลือกไฟล์ `.vzsave`/`.json` → ตรวจ app, checksum, schemaVersion (migrate ถ้าเก่า) → แสดงตัวอย่าง (วันที่, คำที่จำได้, ด่านที่ปลดล็อก, เวลาเล่น)
- ให้เลือก **แทนที่** หรือ **รวม (merge)** โดย snapshot อัตโนมัติก่อนทุกครั้ง
- **กติกา merge** (ใช้ซ้ำในรอบ 8):
  - SRS แต่ละคำ: ใช้ระเบียนที่ `lastReviewedAt` ใหม่กว่า
  - ตัวนับสถิติ: เอาค่ามากกว่า
  - ของที่ปลดล็อก: รวมกัน (union)
  - คำศัพท์ custom: รวมกันตาม id พร้อมตรวจคำซ้ำ
  - settings: คงของเครื่องนี้ (มีตัวเลือกใช้ของไฟล์)
  - checkpoint: ใช้อันที่ใหม่กว่า

### 1.5 เตือนสำรองข้อมูล
- Settings → Data แสดง "สำรองล่าสุด X วันก่อน"
- ถ้ายังไม่ได้เข้าสู่ระบบ และไม่ได้ส่งออกเกิน 7 วันทั้งที่มีความคืบหน้าใหม่ → เตือนเบา ๆ ในเมนูหลัก (ปิดได้ เตือนไม่เกินทุก 3 วัน)
- ข้อความเตือนอธิบายว่า Safari อาจลบข้อมูลของเว็บที่ไม่ได้เปิดใช้งานนาน และแนะนำให้ "เพิ่มลงหน้าจอโฮม" (PWA) กับสำรองไฟล์ไว้
- ปุ่มรีเซ็ตความคืบหน้าต้องพิมพ์ยืนยัน และ snapshot อัตโนมัติก่อนรีเซ็ต

### เกณฑ์ผ่านรอบ 1
- ส่งออก → นำเข้า ได้ข้อมูลเหมือนเดิมทุกฟิลด์ (deep equal)
- ไฟล์เสียหายหรือ checksum ผิดถูกปฏิเสธพร้อมข้อความชัดเจน
- migration จาก fixture ผ่าน
- จำลองปิดแท็บระหว่างเขียน แล้วข้อมูลไม่เสีย
- เช็กลิสต์ทดสอบบน iPad ให้ผู้ใช้ (ส่งออกไปแอป Files → ลบข้อมูลเว็บ → นำเข้ากลับ)

## รอบ 2 — ปุ่มรายงานบั๊ก + รายงานคำศัพท์ (ทำได้ทันที)

### 2.1 ตัวเก็บข้อมูลวินิจฉัย (เปิดตลอด แต่เบา)
- ring buffer เก็บ:
  - console log 200 บรรทัดล่าสุด (ครอบ `console.*` โดยไม่ทำให้ของเดิมพัง)
  - error ทั้งหมดพร้อม stack (`window.onerror`, `unhandledrejection`)
  - event 50 รายการล่าสุดจาก Event Bus
  - FPS ทุก 1 วินาทีย้อนหลัง 120 วินาที (avg/min/1% low) + จำนวนเฟรมที่นานเกิน 50 ms
- ห้ามสร้าง object ใหม่ทุกเฟรมเกินจาก ring buffer · overhead < 0.2 ms/เฟรม

### 2.2 หน้าต่างรายงานบั๊ก (openModal)
- เปิดได้จาก: เมนู Pause, Settings → Help/Support, HELP ในเมนูหลัก, ปุ่มลัด (ปุ่มว่าง ปรับได้ใน key remap)
- เมื่อเกิด error ที่ไม่ได้ดักไว้ ให้ขึ้น toast เล็ก ๆ "เกิดข้อผิดพลาด — แตะเพื่อบันทึกรายงาน" โดยไม่หยุดเกมถ้ายังเล่นต่อได้
- ช่องกรอก:
  - หมวด: Crash/ค้าง, ภาพ, เสียง, การควบคุม/Touch, คำศัพท์/คำอธิบาย, ประสิทธิภาพ, อื่น ๆ
  - คำอธิบาย
  - ปุ่มลัด "ตอนนั้นกำลังทำอะไร" (ยิง, รีโหลด, เปิดประตู, ตอบคำถาม, เปลี่ยนด่าน ฯลฯ)
  - แนบภาพหน้าจอ (ค่าเริ่มต้นเปิด)
  - แนบ UID (ค่าเริ่มต้นปิด)

### 2.3 เนื้อหารายงาน
- เวอร์ชัน (`version.json` + build hash), เวลาท้องถิ่นและ UTC
- อุปกรณ์: user agent, ขนาดจอ, DPR, แนวจอ, อุปกรณ์อินพุตล่าสุด
- กราฟิก: quality tier, FPS cap, สถิติ FPS, `renderer.info` (calls, triangles, geometries, textures, programs), ชื่อ GPU ถ้าเบราว์เซอร์ให้
- เสียง: สถานะ AudioContext และจำนวนเสียงที่เล่นอยู่
- settings ที่เกี่ยวข้อง
- **ภาพรวมเกม**: ฉาก, ด่าน, ชั้น, เวฟ, ซอมบี้ที่ยังอยู่แยกตามชนิด, HP/stamina/ตำแหน่งผู้เล่น, ปืนที่ถือ + สถานะ Weapon State Machine + อุปกรณ์เสริม + ขั้นอัปเกรด, คำถามหรือคำศัพท์ที่กำลังแสดง
- log, error และ event ล่าสุด
- **ภาพหน้าจอ**: จับ canvas ทันทีหลัง render (toBlob) เป็น JPEG กว้าง ≤ 1280 px · HUD ที่เป็น HTML ให้แนบค่าเป็น JSON แทน

### 2.4 รูปแบบผลลัพธ์
- **บันทึกไฟล์** `.vzreport` (JSON + ภาพแบบ base64) ด้วย share/ดาวน์โหลด
- **"คัดลอกสรุปให้ Claude Code"** — ข้อความ Markdown ไม่เกิน ~3,000 ตัวอักษร มีข้อมูลสำคัญและ stack บรรทัดบน ๆ
- เก็บรายงาน 10 ฉบับล่าสุดไว้ในเครื่อง ส่งออกซ้ำได้

### 2.5 รายงานคำศัพท์ (สำคัญ เพราะคำแปลและคำอธิบายบางส่วนเขียนโดย AI)
- ปุ่ม "รายงานคำนี้" (ไอคอนธง) ในหน้าต่างคำอธิบายคำตอบ, vocab log และการ์ดคำศัพท์
- ฟอร์มสั้น: ประเภทปัญหา (ความหมาย/คำแปลผิด, POS ผิด, ตัวอย่างประโยคไม่ดี, คำอธิบายผิด, การสะกด/เสียงอ่าน, อื่น ๆ) + หมายเหตุ

### 3.2 กติกา balance (ค่าเริ่มต้นใน config)
- **จำนวนนัดจนซอมบี้ล้ม (STK)** เทียบ Shambler เวฟ 1 (ลำตัว/หัว):

  | คลาส | STK ลำตัว | STK หัว |
  |---|---|---|
  | ปืนพก | 3–4 | 1–2 |
  | SMG | 4–6 | 2–3 |
  | ไรเฟิล | 2–3 | 1 |
  | LMG | 3–4 | 1–2 |
  | ลูกซอง | 1 (≤5 m) / 2–3 (ระยะกลาง) | 1 |
  | DMR/สไนเปอร์ | 1–2 | 1 |
  | anti-materiel | 1 (+ทะลุ) | 1 |

- **ตามเวฟ**: คำนวณ STK ที่เวฟ 1/5/10/15/20 ด้วยสูตรเพิ่ม HP ซอมบี้ของเกมเดิม เป้าหมายคือ ปืนที่ไม่อัปเกรดที่เวฟ 20 ใช้นัดมากขึ้น ~2–3 เท่า ส่วน Tier III กลับมาใกล้ STK ของเวฟ 5 (จูงใจให้อัปเกรดแต่ไม่ถูกบังคับ)
- **งบความแรงตาม rarity** (ตัวคูณ sustained DPS): common 1.00 · uncommon 1.10 · rare 1.20 · epic 1.32 · legendary 1.45 · secret 1.60
- **Point-buy**: ค่าที่สูงกว่าค่ากลางของคลาสต้องจ่ายด้วยค่าอื่นที่ต่ำลง เครื่องมือคำนวณ "budget score" และติดธงตัวที่เกิน
- **ความต่างของปืน**: ทำเวกเตอร์ค่าพลังแบบ normalize ถ้าปืนในด่านเดียวกันคู่ใดห่างกันน้อยกว่า 0.15 ให้ติดธง · ทุกกระบอกต้องมี niche tag ไม่ซ้ำกันภายใน (ด่าน, rarity) เช่น "ระยะประชิดรัว", "แม่นระยะไกล", "ทะลุฝูง", "คล่องตัว"
- น้ำหนักต้องสอดคล้องกับระบบเดิม (ความเร็วเดิน, เวลา ADS, เวลาหยิบ)
- การทะลุและดาเมจพิเศษต้องเป็นไปตามกติกาคำศัพท์เดิม

### 3.3 เครื่องมือ `tools/balance` (Node)

## รอบ 4 — อาวุธระยะประชิดหลายแบบ

### 4.1 ช่อง Melee
ช่อง "Knife" บน HUD กลายเป็นช่อง Melee ที่แสดงชื่ออาวุธจริง (i18n) · ปุ่ม quick melee ใช้อาวุธในช่องนี้ · ได้อาวุธใหม่แล้วแทนที่อันเดิม

### 4.2 อาวุธและจุดที่พบ (ค่าเริ่มต้น ปรับได้)
ซื้อจากผนังแบบปืนติดผนัง Claude Code เลือกตำแหน่งจริงแล้วรายงาน

| อาวุธ | ด่าน/จุดที่พบ | ท่า | ง้าง / โดน / คืนตัว (ms) | ระยะ | เป้าสูงสุด | Stagger | Stamina/ครั้ง | จุดเด่น |
|---|---|---|---|---|---|---|---|---|
| มีด (เริ่มต้น) | ทุกด่าน | แทง | 80 / 60 / 180 | 1.6 m | 1 | เบา | 5 | เร็ว ยิงหัว ×2 |
| ไม้เบสบอล | โรงเรียน — ห้องเก็บอุปกรณ์พละ | ฟาดแนวนอน 90° | 180 / 90 / 320 | 2.1 m | 3 | หนัก | 12 | ผลักกระเด็น ทุบหมวก Ironclad ได้เร็ว |
| มีดพร้า | โรงเรียน — โรงเก็บของข้างสวนดอกไม้แห้ง | ฟันเฉียง 70° | 140 / 80 / 260 | 1.9 m | 2 | กลาง | 9 | ดาเมจสูงกับตัวที่ไม่มีเกราะ |
| ขวานดับเพลิง | โรงพยาบาล — ตู้ฉุกเฉิน | จามจากบนลงล่าง | 260 / 100 / 420 | 2.2 m | 1 | หนักมาก | 18 | ทำลายเกราะ มีท่าชาร์จ |
| ชะแลง | โรงพยาบาล — ห้องซ่อมบำรุง | ฟาด + เกี่ยว | 170 / 80 / 300 | 2.0 m | 2 | หนัก | 11 | สมดุล โดนโลหะแล้วเสียงดัง |
| พลั่วสนาม | บังเกอร์ — คลังเสบียง | ตักฟาดต่ำ | 200 / 90 / 340 | 2.0 m | 2 | หนัก | 13 | ฟาดเป้าต่ำแม่น (Crawler/Runt) |

- **ท่าชาร์จ** (กดค้าง 0.6–0.9 วินาที): ไม้เบสบอล ขวาน พลั่ว → ดาเมจ ×1.8 ใช้ stamina เพิ่ม
- **คอมโบเบา 2 จังหวะ** (สลับทิศ): มีด มีดพร้า ไม้เบสบอล
- **เป้าต่ำ**: ท่าฟาดลง (overhead) และพลั่วโดนเป้าต่ำแน่นอน ท่าฟาดแนวนอนระดับลำตัวอาจพลาด Crawler ถ้าไม่ก้มมอง
- **Bloater**: ตีระยะประชิดแล้วระเบิดใส่ตัวเอง ต้องมีสัญญาณเตือนตามระบบเดิม

### 4.3 แอนิเมชัน (ผ่าน state Melee ของ Weapon State Machine)
- ง้าง → แนวฟัน → **hitstop 40–70 ms ตอนโดน** (ปรับตาม Screen Effects/Reduce Motion) → follow-through → คืนตัว
- มีท่าหยิบ/เก็บ และท่า inspect ของแต่ละอาวุธ · กล้องสั่นเล็กน้อยตามค่าตั้ง

### 4.4 การตรวจการโดน
ใช้พื้นที่กวาดตามแนวฟัน (sample รูปโค้งหรือ capsule ตลอดเฟรมที่โดน) ไม่ใช่ raycast เส้นเดียว · ชนผนังแล้วหยุด เล่นเอฟเฟกต์และเสียงตาม surfaceType มือสะท้อนกลับ ("แก๊ง") · ห้ามโดนทะลุผนัง

### 4.5 เสียง (ผ่าน sound bank ของระบบเสียงกลาง)
- **วูบ (whoosh)** ตามความเร็วและน้ำหนัก: มีดบางและแหลม · ไม้เบสบอลทุ้มหนัก
- **เสียงโดน** ตามพื้นผิวและเนื้อ: ไม้ = "ปึก" ทึบ · มีดพร้า = เฉือน · ขวาน = จาม + กรอบ · ชะแลง/พลั่ว = โลหะ "แก๊ง" เมื่อโดนของแข็ง
- แยกเสียงฟันพลาดกับฟันโดน · มีเสียงเอี๊ยดตอนชาร์จ · เหตุการณ์ละ 3–4 variants · จำกัดจำนวนเสียงพร้อมกัน

### 4.6 อื่น ๆ
- เอฟเฟกต์เศษตามพื้นผิว และเลือดตามค่า Blood & Gore (Runt ใช้แบบ Reduced เสมอ)
- ปุ่ม Melee บน touch (ย้าย/ปรับขนาดได้) กดค้างเพื่อชาร์จ
- ใส่ข้อมูลอาวุธระยะประชิดในตารางค่าพลัง (หมวด melee) และแสดงการ์ดค่าพลังของตัวเอง

## รอบ 5 — อุปกรณ์เสริมและสกินปืน

### 5.1 อุปกรณ์เสริม — ได้อย่างเสียอย่าง (sidegrade) ไม่ใช่อัปเกรดล้วน
| หมวด | ตัวเลือก | ผลตัวอย่าง (ค่าเริ่มต้น) |
|---|---|---|
| Optic | Red Dot, Holo, 2x, 4x, 8x (สไนเปอร์) | ซูมมากขึ้น แต่ ADS ช้าลง และส่ายมากขึ้นตอนเล็ง |
| Muzzle | Suppressor, Compensator, Muzzle Brake | Suppressor: เสียงเบา ไม่มีแสงไฟ ระยะ −10% · Compensator: แรงถีบแนวตั้ง −20% แสงไฟ +5% · Brake: แรงถีบรวม −15% เสียงดังขึ้น |
| Magazine | Extended, Fast-Mag | Extended: แม็ก +50% รีโหลด +10% ADS −5% · Fast-Mag: รีโหลด −20% แม็ก −10% |
| Grip/Laser | Vertical Grip, Angled Grip, Laser | Vertical: แรงถีบ −15% ADS ช้าลง · Angled: ADS เร็วขึ้น · Laser: spread จากสะโพก −25% แต่เห็นจุดเลเซอร์ |

### 5.2 การติดตั้ง
- ตารางความเข้ากันได้ตามตระกูลปืน (เช่น ปืนพกใส่ red dot/suppressor/แม็กยาวได้)
- ข้อมูลจุดยึดต่อกระบอก: rail, ปลายลำกล้อง, ช่องแม็ก, ใต้ลำกล้อง → วางโมเดล voxel ของอุปกรณ์อัตโนมัติ
- **ตำแหน่งภาพตอน ADS ต่อ optic × ปืน** เก็บเป็นข้อมูล + เครื่องมือใน Weapon Lab สำหรับปรับและบันทึก
- โมเดลอุปกรณ์ใช้สไตล์ HD-blocky และพาเลตเดียวกับปืน · เป้า Red Dot เป็นจุดแดง · Holo เป็นวงกลม + จุด · กล้องขยายเป็นวงแหวนเหลี่ยมแบบ low-poly (ส่ายตามค่า Reduce Motion)

### 5.3 ตระกูลเสียงปืนเก็บเสียง (suppressed)
- หัวเสียงเบาลง ~12 dB และแคบลงเหลือ 800–2000 Hz
- เนื้อเสียงสั้นแบบ "ทึบ" (sine 200→120 Hz)
- **เสียงกลไก (สไลด์/โบลต์) เด่นขึ้น** ~+6 dB เมื่อเทียบกับเสียงยิง
- หางเสียงลด −20 dB ภายใน ≤ 0.2 วินาที และไม่มี echo ระยะไกล
- สไนเปอร์คงเสียง "แคร็ก" จาง ๆ ไว้ได้ (ตัวเลือก)
- ตรวจเป้าหมายด้วยตัวเลขแบบเดียวกับหัวข้อ 5 ของ GUN_REFERENCE.md
- ถ้า AI ซอมบี้มีระบบได้ยินเสียง ให้ลดรัศมี aggro ของปืนเก็บเสียง ถ้าไม่มีให้ข้ามไป

### 5.4 สกิน (ความสวยงามล้วน ไม่มีผลต่อค่าพลัง)
- 8 ชุดสีพื้นฐานจากพาเลตที่วัดไว้: ดำ/เหล็ก · ไม้ + เหล็ก · ดำ + FDE · เงิน + ดำ · เขียวขี้ม้า + ดำ · ขาว + ดำ · gunmetal + น้ำตาล · ดำ + เลนส์น้ำเงิน
- สกินพิเศษธีมการเรียน เช่น "Lexicon" (ลายตัวอักษรหมึก), "Scholar Gold", ลายพรางประจำหัวข้อ (Environment, Education, Health ฯลฯ)
- **ทุกสกินต้องคงสี accent ประจำกระบอก** (แถบสี/ศูนย์เรืองแสง) เพื่อให้จำปืนได้ตามกติกาเดิมที่ปืนแต่ละกระบอกมีสีสันเฉพาะ

### 5.5 ปลดล็อกจากความคืบหน้าการเรียน (ถาวร ระดับบัญชี/เซฟ)
| เงื่อนไข | ตัวอย่างของที่ปลดล็อก |
|---|---|
| จำคำได้ (กล่อง 4–5) 25 / 50 / 100 / 250 / 500 คำ | Red Dot → Extended Mag → 4x → Suppressor → สกิน Scholar Gold |
| Daily Review ต่อเนื่อง 3 / 7 / 14 / 30 วัน | Holo → Fast-Mag → Angled Grip → สกิน Lexicon |
| ทำ word family ครบ 5 / 15 ตระกูล | Compensator / Muzzle Brake |
| หัวข้อใดหัวข้อหนึ่งจำได้ ≥ 80% | ลายพรางประจำหัวข้อนั้น |
| สะกดคำถูกโดยไม่ใช้คำใบ้ติดกัน 20 ครั้ง | Laser |
| เก็บ story notes ครบด่าน | สกินประจำด่าน |
| ชนะบอสครบ 4 ตัวในหนึ่งรอบ | 8x scope |
- ตอนปลดล็อกขึ้น toast (ไม่ขัดจังหวะเกม) และเพิ่มรายการใน AWARDS

### 5.6 การตั้งค่าที่ใช้
- เมนู WEAPONS → เลือกอุปกรณ์เสริมที่ต้องการต่อกระบอก (หรือค่าเริ่มต้นต่อตระกูล) และเลือกสกิน → **ติดให้อัตโนมัติเมื่อได้ปืนนั้นระหว่างเล่น**
- ระหว่างเล่นเปลี่ยนได้เฉพาะที่ร้านค้าหรือ Word Forge (ตั้งค่าได้ใน config)
- การ์ดค่าพลังแสดงผลของอุปกรณ์เสริม

### เกณฑ์ผ่านรอบ 5
- ภาพ ADS ตรงทุกชุดที่ใส่ได้ (ภาพหน้าจออัตโนมัติต่อ optic × ตระกูล)
- เสียงปืนเก็บเสียงผ่านเป้าตัวเลข
- ทดสอบการปลดล็อกด้วยความคืบหน้าจำลอง
- balance report รวมผลของอุปกรณ์เสริม

## รอบ 6 — Word Forge: โต๊ะอัปเกรดด้วยคำศัพท์

### 6.1 สถานี
- ชื่อชั่วคราว **"Word Forge"** (ห้ามใช้ชื่อ "Pack-a-Punch" ซึ่งเป็นของเกมอื่น)
- ด่านละ 1 จุดในห้องที่จำง่าย (Claude Code เลือกแล้วรายงาน เช่น ห้องวิทยาศาสตร์ / ห้องแล็บ / คลังอาวุธ)
- มองเห็นได้จากไกล (แสงเรือง + เสียงฮัมเบา ๆ) · โต้ตอบด้วย E/แตะ

### 6.2 ขั้นอัปเกรด (ต่อกระบอก ค่าจากตารางค่าพลัง)
- **Tier I–III** เพิ่มค่าพลังตามข้อมูล
- Tier III ได้ความสามารถเด่นตาม niche เช่น ทะลุ +1, แม็กใหญ่ขึ้น, โบนัสยิงหัว — ต้องเคารพกติกาคำศัพท์
- **ภาพ**: แถบสีประจำขั้น + ลายเรืองแสง + ป้าย Mk II / Mk III
- **เสียง**: เนื้อเสียงหนักขึ้น (sub +2–3 dB, pitch ต่ำลง ~3%) + หางเสียงเพิ่มอีกชั้น
- แสดง tier บนแผงขวาของ HUD · การ์ดค่าพลังแสดงตัวอย่างส่วนต่างก่อนอัปเกรด

### 6.3 ค่าใช้จ่าย = เงิน (ตาม tier และ rarity) + ภารกิจคำศัพท์
| Tier | จำนวนข้อ | เกณฑ์ผ่าน | เงื่อนไขเพิ่ม |
|---|---|---|---|
| I | 4 | ≥ 3 ถูก | คำถามแบบเลือกตอบได้ |
| II | 5 | ≥ 4 ถูก | อย่างน้อย 1 ข้อเป็นแบบนึกคำเอง (สะกด/พิมพ์ หรือฟัง) |
| III | 5 | 5/5 | อย่างน้อย 2 ข้อนึกคำเอง และห้ามใช้คำใบ้ |

- **ลำดับการเลือกคำ**:
  1. คำใน confusion list ส่วนตัวหรือคำที่เพิ่งตอบผิด
  2. คำที่ถึงกำหนดทบทวนใน SRS (กล่อง 1–3)
  3. คำของด่านนี้ที่ระดับ CEFR สูงกว่า
- **ห้ามใช้คำที่ผู้เล่นยังไม่เคยเห็น** · ใช้คำถามหลายแบบ · แต่ละครั้งที่ลองใช้คำไม่ซ้ำกัน
- ทุกข้อแสดงคำอธิบายตอบถูก/ผิดตามระบบคำอธิบายของ overhaul รอบ 7
- **สอบไม่ผ่าน**: เสียเงิน 50% ไม่ได้อัปเกรด และลองกับปืนกระบอกนั้นได้อีกครั้งหลังจบเวฟปัจจุบัน (กันการเดาสุ่มรัว ๆ)
- ระหว่างทำภารกิจ เกมหยุด (openModal) · ตัวเลือกใน config `forgeOnlyBetweenWaves` สำหรับให้ใช้ได้เฉพาะช่วงพักระหว่างเวฟ

### 6.4 การเรียน
- คำตอบทุกข้อนับเป็นการทบทวนตามกฎ SRS เดิม
- จบแล้วสรุป: "ทบทวน N คำ · ถูก M คำ · คำที่ควรกลับมาดู" แตะดูการ์ดคำได้

### 6.5 แอนิเมชันและการเก็บค่า
- ฉากอัปเกรด 2–3 วินาที (วางปืนบนโต๊ะ → ประกายไฟ → เรืองแสง → เสียงตีเหล็ก) ข้ามได้หลังเห็นครั้งแรก
- อัปเกรดเป็นของรอบเล่นนั้น (รีเซ็ตเมื่อ Game Over เหมือนปืน) · checkpoint เวฟ 10 เก็บค่านี้ตามที่ระบบเดิมเก็บปืน

### เกณฑ์ผ่านรอบ 6
- test ตรวจกติกาเลือกคำ (ไม่มีคำใหม่ ลำดับความสำคัญถูก)
- cooldown หลังสอบไม่ผ่านทำงาน
- SRS อัปเดตถูกต้อง
- balance report มีครบทุก tier

## รอบ 7 — ด่านสอนเล่น + คำแนะนำตามสถานการณ์

### 7.1 การเข้าถึง
- เสนอครั้งแรกหลังผู้เล่นตั้งค่าภาษา: "เล่นด่านสอน" / "ข้าม"
- เข้าซ้ำได้จากเมนูหลัก (HELP หรือ PLAY → Tutorial) · ข้ามได้ทุกเมื่อจากเมนู Pause

### 7.2 ฉาก
"Training Yard" เล็ก ๆ สร้างจากชิ้นส่วนของโรงเรียน (ลานหน้า + ทางเดิน 1 ช่วง + ห้องเรียน 1 ห้อง) แสงเช้าสงบ โหลดเร็ว ไม่เปิดเผยเนื้อเรื่อง

### 7.3 ขั้นตอน
ผ่านขั้นละอย่าง ไปขั้นถัดไปเมื่อทำสำเร็จเท่านั้น · ถ้าค้างเกิน 20 วินาทีให้คำใบ้ชัดขึ้น · มี checkpoint ทุกขั้น · รวม 5–8 นาที
1. มองและเดิน
2. วิ่ง + แถบ stamina
3. **ยิงเป้าตามความหมายคำ** — ใช้หุ่นนิ่งกับคำฝึก แสดงกล่องคำถามด้านบน และการ์ดคำอธิบายเมื่อยิงผิด
4. เล็ง (ADS) + รีโหลด
5. สลับอาวุธ (ปุ่มตัวเลข / ล้อเมาส์ / แตะช่อง) + อาวุธระยะประชิด
6. เก็บเงิน + ซื้อปืนติดผนัง (Savings)
7. เปิดประตู (E) + ประตูคำศัพท์
8. ทัวร์ HUD (HP %, stamina, ช่องอุปกรณ์, แผงขวา, แถบ Wave)
9. เวฟจำลอง: Shambler 4–6 ตัว + Crawler 1 ตัว
10. Quiz ท้ายเวฟ (ย่อเหลือ 3 ข้อ) + เลือก perk
11. การ์ดแนะนำสั้น ๆ: Word Forge, อุปกรณ์เสริม/สกินที่ปลดล็อกจากการเรียน, Daily Review/SRS, vocab log, การรายงานบั๊กและรายงานคำศัพท์

### 7.4 รายละเอียด
- **ข้อความตามอุปกรณ์**: ตรวจอินพุตล่าสุด (keyboard/mouse, controller, touch) แล้วแสดงสัญลักษณ์ปุ่มให้ตรง · บน touch ให้ไฮไลต์ปุ่มบนจอ
- **คำฝึก**: ชุดคำง่ายตายตัว (A2–B1) ตาม Word Language **ไม่นับเข้า SRS หรือสถิติ**
- เคารพ Reduce Motion และขนาดตัวอักษรที่ตั้งไว้

### 7.5 คำแนะนำตามสถานการณ์ (แสดงครั้งเดียวต่อโปรไฟล์)
- จุดที่แสดง: เจอบอสครั้งแรก, เจอ Bloater/Screamer/Ironclad ครั้งแรก, ร้าน perk ครั้งแรก, Word Forge ครั้งแรก, ปลดล็อกอุปกรณ์เสริมครั้งแรก, ปลดล็อกชั้นครั้งแรก, เจอ story note ครั้งแรก, กระสุนใกล้หมดครั้งแรก
- เป็นการ์ดเล็กที่ไม่หยุดเกม มีปุ่ม "เข้าใจแล้ว" / "ไม่ต้องแสดงคำแนะนำ"
- เปิด/ปิดได้ใน Settings → Tips

- tips แสดงครั้งเดียว

## รอบ 8 — บัญชีผู้ใช้ + ซิงก์คลาวด์ + โปรไฟล์

### 8.1 แนวทาง
- **Firebase Authentication + Cloud Firestore** (modular web SDK ติดตั้งผ่าน npm แล้ว bundle/เสิร์ฟจาก `public/` ให้ service worker cache ได้)
- **เล่นแบบไม่เข้าสู่ระบบ (guest) เป็นค่าเริ่มต้น** — ใช้ anonymous auth หรือเก็บในเครื่องล้วน แล้วเชื่อมบัญชีภายหลังโดยข้อมูลไม่หาย (link credential)
- บน iPad Safari popup อาจถูกบล็อก → ต้องมี redirect flow สำรอง

### 8.2 ผู้ให้บริการเข้าสู่ระบบ
Google (ทำก่อน) · Facebook · Apple — แต่ละตัวมี flag ใน config ถ้ายังไม่มีคีย์ให้ซ่อนปุ่มนั้น

### 8.3 UID สาธารณะ 9 หลักที่ไม่ซ้ำ
- สุ่ม 100000000–999999999 → จองด้วยเอกสาร `publicIds/{id}` ที่สร้างได้ครั้งเดียว
  - security rule: create ได้เมื่อเข้าสู่ระบบแล้ว และ `request.resource.data.uid == request.auth.uid` · ห้าม update · ลบได้เฉพาะเจ้าของตอนลบบัญชี
  - ถ้าซ้ำให้สุ่มใหม่
- เก็บใน `users/{uid}.publicId` · แสดงในแถบ UID ของเมนูหลักและหน้าโปรไฟล์ พร้อมปุ่มคัดลอก

### 8.4 ชื่อที่แสดง
- 1–8 ตัวอักษร **นับแบบ grapheme** (`Intl.Segmenter` เพื่อให้สระและวรรณยุกต์ไทยนับถูก)
- ตัดช่องว่างหัวท้าย · ห้าม control characters · ตัวกรองคำหยาบเบื้องต้น (ไทย/อังกฤษ ใน config)
- ไม่ต้องไม่ซ้ำ (UID แยกตัวตนอยู่แล้ว) · เปลี่ยนได้วันละครั้ง

### 8.5 รูปโปรไฟล์
- เลือกจากคลังภาพ/ไฟล์ (`input type=file accept=image/*`) → UI ครอปสี่เหลี่ยม (ลาก/ซูม)
- ย่อเป็น 128×128 แล้วบีบอัด (WebP ถ้ารองรับ ไม่งั้น JPEG) ให้ ≤ 60 KB
- **เก็บเป็น base64 ในเอกสาร Firestore** (เลี่ยงการพึ่ง Firebase Storage ซึ่งอาจต้องใช้แผนแบบจ่ายตามการใช้งาน — ตรวจเงื่อนไขปัจจุบัน)
- มี avatar เริ่มต้นเป็นหัว voxel ผู้รอดชีวิตหลายแบบ

### 8.6 หน้าโปรไฟล์
เข้าจาก PROFILE ในเมนูหลัก หรือแตะแถบ UID
- **ซ้าย**: avatar, ชื่อ, UID, บัญชีที่เชื่อมไว้, สถิติ (เวลาเล่น, คำที่จำได้, streak, เวฟสูงสุดต่อด่าน)
- **ขวา**: ตารางคำศัพท์แบบแท็บ
  - **ตอบถูกมากที่สุด** (10 อันดับ)
  - **ตอบถูกน้อยที่สุด** (ความแม่นต่ำสุด เฉพาะคำที่ตอบ ≥ 3 ครั้ง)
  - **ตอบผิดบ่อยที่สุด** + คู่คำที่สับสน
  - แตะคำแล้วเปิดการ์ดคำพร้อมคำอธิบายและเสียงอ่าน

### 8.7 เซฟบนคลาวด์
- `users/{uid}/save/main` = เซฟบีบอัด (CompressionStream gzip → base64 ถ้ารองรับ) ≤ 900 KB ถ้าเกินให้แบ่งเป็น `save/part-N`
- metadata: schemaVersion, updatedAt, deviceId, สรุปสั้น
- **offline-first**: ส่งขึ้นเมื่อจบเวฟ, จบรอบ, settings เปลี่ยน (debounce 10 วินาที), แอปถูกซ่อน · เขียนไม่เกิน 1 ครั้ง/30 วินาที · ดึงลงตอนเข้าสู่ระบบและตอนเปิดแอป
- ไอคอนสถานะในเมนูหลัก: ซิงก์แล้ว / กำลังซิงก์ / ออฟไลน์ / ผิดพลาด

### 8.8 เมื่อข้อมูลชนกัน (ตอนเข้าสู่ระบบหรือเชื่อมบัญชี)
ถ้ามีข้อมูลทั้งในเครื่องและบนคลาวด์ → แสดงสรุปของทั้งสองฝั่ง ให้เลือก: ใช้ของคลาวด์ / ใช้ของเครื่องนี้ / **รวม (แนะนำ)** ตามกติกา merge ของรอบ 1 · snapshot อัตโนมัติก่อนทุกครั้ง

### 8.9 Security Rules
- `users/{uid}` อ่าน/เขียนได้เฉพาะเจ้าของ
- ตรวจชนิดและขนาดฟิลด์: ชื่อ ตรวจละเอียดฝั่ง client (8 grapheme) ส่วนใน rules ตรวจหยาบ ๆ ว่าไม่เกิน 32 ตัวอักษร เพราะ rules นับ grapheme ไม่ได้ · avatar ≤ 80 KB · ชิ้นเซฟ ≤ 900 KB
- `publicIds` สร้างได้อย่างเดียว · ที่เหลือปฏิเสธทั้งหมด
- ทดสอบด้วย **Firebase Emulator Suite + `@firebase/rules-unit-testing`**

### 8.10 ลบบัญชีและสิทธิ์ในข้อมูล
- Settings → Account → ลบบัญชี (ต้องยืนยันตัวตนใหม่) → ลบ save, publicId, user doc แล้วลบผู้ใช้ใน Auth · ให้เลือกว่าจะเก็บหรือล้างข้อมูลในเครื่อง
- ดาวน์โหลดข้อมูลของตัวเองได้ (ใช้ export ของรอบ 1)

### 8.11 นโยบายความเป็นส่วนตัวและความยินยอม
- หน้า `/privacy.html` (4 ภาษา): เก็บอะไร (รหัสบัญชีจากผู้ให้บริการ, ชื่อที่แสดง, avatar, ความคืบหน้าการเรียน), เพื่ออะไร, เก็บที่ไหน, นานเท่าไร, ลบอย่างไร, ติดต่อใคร
- หน้า `/data-deletion.html` วิธีลบข้อมูล (Meta และ Apple ต้องใช้ URL เหล่านี้)
- ช่องติ๊กยอมรับตอนเข้าสู่ระบบครั้งแรก · ไม่เก็บอีเมลลง Firestore ถ้าไม่จำเป็น
- ถ้าผู้เล่นอาจเป็นนักเรียนหรือผู้เยาว์ ให้มีข้อความเรื่องความยินยอมของผู้ปกครองตาม PDPA และแจ้งผู้ใช้ให้ปรึกษาผู้รู้ก่อนเปิดให้คนอื่นใช้จริง

### 8.12 คู่มือตั้งค่าสำหรับผู้ใช้ (ผู้ใช้ต้องทำเอง Claude Code ทำแทนไม่ได้)
เขียน `docs/expansion/ACCOUNT_SETUP.md` เป็นภาษาไทยทีละขั้น:
1. สร้างโปรเจกต์ Firebase → ลงทะเบียน Web App → คัดลอก config ไปไว้ที่ `public/firebase-config.js` (config ของเว็บเปิดเผยได้ ความปลอดภัยอยู่ที่ security rules)
2. เปิด Authentication → Google · ใส่โดเมนของเว็บ (Cloudflare) ใน Authorized domains · ตั้ง OAuth consent screen
3. Facebook: สร้างแอปใน Meta for Developers → App ID/Secret → ใส่ Privacy Policy URL และ Data Deletion URL → เปิดเป็น Live
4. Apple: **ต้องสมัคร Apple Developer Program แบบเสียเงินรายปี** → สร้าง Services ID, key, return URL (ข้ามไปก่อนได้)
5. สร้าง Firestore (เลือก region ใกล้ไทย เช่น asia-southeast1) → deploy rules
6. ตรวจโควตาแผนฟรีและราคาปัจจุบันในหน้า Firebase (ห้ามอ้างตัวเลขจากความจำ) และออกแบบให้อ่าน/เขียนน้อยที่สุด

### 8.13 ถ้ายังไม่มีคีย์
ทำโค้ดทั้งหมดและทดสอบกับ emulator ปิด feature flag ใน production แล้วไปรอบ 9 ได้เลย · แจ้งผู้ใช้ว่ารอคีย์อะไร

### เกณฑ์ผ่านรอบ 8

## รอบ 9 — ทดสอบรวม + deploy
- รัน test ทั้งหมด: schema ข้อมูลปืน, balance report, การเลือกคำของ Word Forge, การปลดล็อก, export/import, migration, security rules (emulator), สคริปต์รายงาน
- ทดสอบประสิทธิภาพ: iPad Medium ≥ 30 FPS และ desktop High ≥ 60 FPS พร้อมระบบใหม่ทั้งหมด (อาวุธระยะประชิด, อุปกรณ์เสริม, ฉาก Word Forge)
- ตรวจ i18n ครบ 4 ภาษา (ไม่มี key ค้าง) และ touch/controller ทุกหน้าจอใหม่
- เพิ่มหน้าต่าง **"มีอะไรใหม่"** แสดงครั้งเดียวหลังอัปเดตเวอร์ชัน (สรุป 7 ระบบนี้ i18n)
- อัปเดตหน้า HELP ให้ครอบคลุมระบบใหม่
- Deploy: ไฟล์อยู่ใน `public/` · ทุกไฟล์ < 25 MiB · เพิ่มเลขใน `version.json` · commit + push `main`
